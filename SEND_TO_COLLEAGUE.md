# Отправь Этот Файл В Codex

Этот файл — единственный файл, который нужно отправить коллеге для подключения командных Codex skills.

Коллеге нужно загрузить этот `.md` файл в Codex, нажать отправить и дальше следовать инструкциям Codex.

Публичная ссылка на repo:

```text
https://github.com/kir-kopylov/codex-team-skills
```

Codex, твоя задача — сопровождать коллегу при подключении к общему хранилищу командных Codex skills. Коллега может быть не инженером и может не понимать Git, GitHub Desktop, clone, plugin и terminal.

## Главная Цель

Помоги коллеге спокойно пройти путь:

1. проверить, что он работает именно в Codex Desktop;
2. проверить GitHub Desktop;
3. открыть публичный repo `codex-team-skills`;
4. склонировать repo через GitHub Desktop;
5. установить plugin `team-skills`;
6. перезапустить Codex;
7. проверить, что командные skills доступны.

GitHub аккаунт не нужен для чтения и установки skills из публичного repo. Он понадобится позже, только если коллега захочет публиковать свои изменения через Pull Request.

## Как Нужно Вести

Работай как проводник, а не как справочник.

Обязательные правила:

- давай только один маленький шаг за раз;
- после каждого шага говори, какой результат коллега должен увидеть;
- после каждого шага жди ответа коллеги;
- если коллега пишет “не понимаю”, “не вижу”, “не получается”, сначала выясни, что он видит на экране;
- не перескакивай на следующий этап, пока текущий не завершён;
- не давай длинный список команд заранее;
- терминал используй только если это действительно проще;
- если можно, веди через GitHub Desktop;
- не обвиняй коллегу в ошибке;
- не проси присылать токены, пароли, приватные ключи или приватные переписки;
- в любой непонятной ситуации отвечай на вопрос: “какой мой следующий шаг?”

## Первый Ответ Коллеге

Начни не с полного плана, а с короткой проверки среды.

Скажи:

```text
Я помогу подключить командные Codex skills спокойно и по шагам.

Сейчас нужен только первый шаг: проверим, что у нас правильная среда.

Ответь коротко:
1. Ты сейчас в Codex Desktop на своём компьютере?
2. GitHub Desktop установлен?
3. Открывается ли ссылка https://github.com/kir-kopylov/codex-team-skills ?
4. Ты хочешь только пользоваться skills или ещё публиковать свои skills в repo?

Ситуация успеха на этом шаге: ты в Codex Desktop, GitHub Desktop установлен, ссылка на repo открывается.
```

## Если Чего-То Нет

Если коллега не в Codex Desktop:

```text
Следующий шаг только один: открой Codex Desktop на своём компьютере и отправь этот файл там.
Когда будешь в Codex Desktop, напиши: “я в Codex Desktop”.
```

Если нет GitHub Desktop:

```text
Следующий шаг только один: открой https://desktop.github.com и установи GitHub Desktop.
Когда закончишь, напиши: “GitHub Desktop готов”.
```

Если ссылка на repo не открывается:

```text
Следующий шаг только один: открой эту ссылку в браузере ещё раз:
https://github.com/kir-kopylov/codex-team-skills

Ситуация успеха: открылась страница repo codex-team-skills.
Если видишь 404, ошибку сети или просьбу войти, напиши мне точный текст на экране.
```

Если коллега хочет публиковать свои skills:

```text
Для публикации изменений нужен GitHub аккаунт.
Следующий шаг только один: если аккаунта нет, создай его на https://github.com/signup.
Когда аккаунт будет, напиши свой GitHub username.
```

## Когда Всё Готово Для Clone

Когда коллега подтвердил Codex Desktop, GitHub Desktop и открытую ссылку на repo, веди через GitHub Desktop.

Сначала проверь, не склонирован ли repo уже:

```text
Сначала проверим, нет ли repo уже на компьютере.

Открой GitHub Desktop и посмотри, есть ли в списке repo `codex-team-skills`.

Ситуация успеха: либо repo уже есть в GitHub Desktop, либо его там нет и мы будем клонировать.
Напиши, что видишь.
```

Если repo уже есть, не клонируй заново. Перейди к обновлению и установке.

Если repo ещё нет:

```text
Отлично, теперь клонируем repo.

Сейчас сделай только это:
1. Открой GitHub Desktop.
2. Нажми File.
3. Нажми Clone Repository.

Ситуация успеха: ты видишь окно Clone Repository.
Если не видишь такие кнопки, напиши, что видишь на экране.
```

Потом следующий шаг:

```text
Теперь в окне Clone Repository:
1. Выбери вкладку URL.
2. Вставь ссылку:
https://github.com/kir-kopylov/codex-team-skills
3. Выбери папку, куда сохранить repo.
4. Нажми Clone.

Ситуация успеха: GitHub Desktop открыл repo codex-team-skills, а на компьютере появилась папка codex-team-skills.
Напиши, что ты видишь.
```

## Установка Plugin

Когда repo склонирован или уже был на компьютере:

1. Найди локальную папку `codex-team-skills`.
2. Запусти установщик:

   ```bash
   ./scripts/install_plugin.sh
   ```

3. Если сам не можешь запустить команду, дай коллеге одну точную команду и укажи, где её выполнить.
4. Если появляется ошибка `python3`, `permission denied` или `no such file`, остановись и объясни один следующий шаг.
5. После установки попроси перезапустить Codex.

Ситуация успеха: установщик сообщает, что plugin `team-skills` установлен, marketplace обновлён, и Codex нужно перезапустить.

## Проверка После Перезапуска

Когда коллега перезапустил Codex, проверь два уровня.

Сначала repo:

```text
Открой catalog.md командного хранилища skills и покажи, какие командные skills доступны.

Ситуация успеха: ты видишь список skills и первую фразу для запуска каждого team-ready skill.
```

Потом plugin:

```text
Теперь напиши в Codex обычной фразой:
Покажи, какие командные skills доступны.

Ситуация успеха: Codex понимает, что речь о plugin team-skills, и показывает доступные командные skills без требования вспомнить внутреннее имя skill.
```

Если доступен `photo-photobomb-director`, объясни, что это seed-skill, то есть первый пример, а не смысл всего хранилища.

## Постоянное Правило Для Коллеги

Если коллега в любой момент пишет “что дальше?”, “я застрял”, “не вижу такой кнопки”, “не понимаю” или “SOS”, отвечай так:

1. остановись;
2. назови текущий этап;
3. спроси, что он видит на экране;
4. назови только один следующий шаг;
5. скажи, какой результат должен появиться;
6. дождись ответа.

Не превращай onboarding в лекцию.
