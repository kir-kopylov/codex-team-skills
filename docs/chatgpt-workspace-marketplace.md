# Командная библиотека в веб-ChatGPT

Администратор подключает репозиторий один раз и задаёт общую установку
`team-skills` в рабочей области. Участникам не требуется копировать файлы
или устанавливать библиотеку на компьютер. Используется существующий
`.agents/plugins/marketplace.json`; отдельный манифест для ChatGPT не нужен.

## Подключение области

1. Проверьте выбранную рабочую область, свой аккаунт и права администратора.
   Проверьте содержимое репозитория и доступ импортирующего GitHub-аккаунта.
2. Откройте **Admin → Marketplaces → Add → Import marketplace**. В варианте
   интерфейса из документации OpenAI вход находится в **Admin → Plugins**.
3. Заполните форму:

   | Поле | Значение |
   | --- | --- |
   | Source | `https://github.com/kir-kopylov/codex-team-skills` |
   | Path | Оставить пустым: манифест расположен относительно корня репозитория |
   | Branch, tag, or commit | `main` |

4. Нажмите **Import marketplace**. Если появляется **Connect GitHub**, пройдите
   штатное подключение. Перед подтверждением прочитайте аккаунт и запрошенные
   разрешения; новый доступ не следует из одного факта открытия формы.
5. Перечитайте карточку каталога: исходный commit, **Latest sync** или
   **Import results**, результат каждого плагина и раскрытые замечания.
   Сверьте commit с `main`, версию — с
   `plugins/team-skills/.codex-plugin/plugin.json`, состав — с каталогом
   `plugins/team-skills/skills/` на этом commit. Успех всего прохода не отменяет
   ошибку отдельного плагина.
6. Откройте «Командные скиллы» (`team-skills`). Проверьте **Enabled**, затем
   выберите **Availability → Workspace default → Installed**. Надпись
   **Applies to everyone in this workspace** задаёт общую область действия.
   Если интерфейс показывает **Installation policy** по ролям, проверьте
   каждую нужную роль. Дождитесь сохранения и перезагрузите карточку:
   **Installed** и область действия должны сохраниться.

Поля формы и настройка общей установки сверены в веб-интерфейсе 30.09.2026
на пакете `0.10.1`. Названия элементов могут измениться. Источник платформенных
правил — [управление каталогами OpenAI](https://learn.chatgpt.com/docs/enterprise/plugin-management).
GitHub поставляет содержимое; доступ и установку задаёт администратор ChatGPT.

## Проверка у участников и ограничения

Участник открывает новый чат в нужной области без ручной переустановки и
отправляет обычный запрос из согласованного примера навыка. Сначала проверяют
один сквозной случай, затем выбор между похожими навыками и отрицательные
примеры. Сохраняют точный запрос, полный ответ, видимые действия и файлы,
время, область, модель и доступную информацию о версии.

Выбор навыка, выполнение процедуры и качество результата оценивают отдельно.
Статус **Installed**, уведомление о запуске и самоотчёт модели не доказывают
выполнение. Если интерфейс не показывает различающих следов, соответствующий
вывод остаётся неподтверждённым. Ответы и снимки участников хранят приватно.

Действуют существующие [правила запуска](transparent-skill-launch.md):
`team-ready` и `experimental` допускают однозначный смысловой запуск;
`draft` и `goal-contract-shaper-v3` — только явный.

Импорт инструкций сам по себе не предоставляет локальные программы,
инструменты Codex, доступ к компьютеру или подключённым сервисам. Для
конкретной задачи проверяют доступные инструменты, используют предусмотренный
навыком запасной путь и прямо называют недоступную часть. Если локальный
журнал обратной связи недоступен, показывают предусмотренную карточку и
сообщают, что запись не сохранена. Успешный импорт не доказывает исполнение
вложенных скриптов.

Если импорт помечен **Desktop only**, пакет недоступен в веб-чате. В частности,
OpenAI применяет эту пометку к плагинам с объявленными MCP-серверами; доступность
проверяют заново при изменении состава пакета.

## Обновление без переустановки

По [документации OpenAI](https://help.openai.com/en/articles/20001504-importing-and-syncing-plugin-marketplaces-from-github)
новые каталоги проверяют обновления ежедневно. Проверьте **Auto-sync**.
Включённый переключатель подтверждает настройку, а не состоявшийся запуск.

1. До полезного изменения сохраните версию, запрос и фактический ответ,
   позволяющие проверить именно изменяемое поведение.
2. Примите изменение обычным процессом репозитория. Решение о merge принимает
   владелец; фиктивная правка ради обновления не нужна.
3. После merge откройте каталог в **Admin → Marketplaces** и нажмите
   **Sync now**. Перечитайте commit и отчёт, включая результат `team-skills`,
   его версию и замечания. Обновление списка страницы не заменяет синхронизацию.
4. Тот же участник в новом чате повторяет проверку без переустановки.
   Доставка нового commit и изменение фактического поведения — два отдельных
   подтверждения. Правка только документации не доказывает изменение навыка.
5. Для проверки ежедневного обновления отдельно прочитайте последующий отчёт
   автоматического запуска и его время. Если доступные сведения не отличают
   автоматический запуск от ручного, ежедневное выполнение не подтверждено.

Для каждого вывода сохраняйте источник, время, проверяемую версию и результат.
Сам импорт и существующий CI не заменяют проверки в сеансе участника.

## Если синхронизация не завершилась

Сначала перечитайте фактическое состояние: операция могла завершиться после
ошибки или задержки интерфейса. Зафиксируйте время, источник, ветку, текущий
commit и сообщение. Старый commit означает «обновление не подтверждено»,
а не разрешение повторять изменение репозитория.

- **Completed — N errors:** разберите ошибку нужного плагина. Некорректное
  обновление оставляет последнюю рабочую версию. Исправьте подтверждённый
  дефект через существующий процесс, после merge запросите **Sync now**
  и снова прочитайте результат.
- **Ошибка GitHub или Missing OAuth callback data:** проверьте карточку
  каталога, прежде чем начинать новое подключение. Если импорт или
  синхронизация уже завершились, повторять авторизацию не нужно. Сам текст
  ошибки не устанавливает причину. При подтверждённой потере доступа
  исходный импортирующий администратор проверяет доступ GitHub к репозиторию
  и переподключает GitHub в ChatGPT: синхронизация использует его подключение.
  Не воспроизводите старую ссылку OAuth и не обходите отказ в разрешении.
- **Исходный администратор недоступен:** новый администратор проверяет свой
  доступ GitHub и импортирует каталог с точно теми же **Source**, **Path**
  и **Branch, tag, or commit**. По документации OpenAI следующие синхронизации
  используют его подключение. После передачи снова проверяют отчёт и
  установку; каталог заранее не удаляют.
- **Каталог или плагин не виден участнику:** проверьте выбранную область,
  **Enabled**, сохранённую общую установку и права участника. Нужные внешние
  сервисы проверяются отдельно; импорт не подключает аккаунты участников.

Не удаляйте каталог ради переподключения: это удаляет импортированные из него
плагины. При сохраняющемся сбое передайте в поддержку точную ошибку и шаги
воспроизведения без токенов и приватных материалов. Порядок восстановления
описан в [разделе OpenAI о доступе GitHub](https://learn.chatgpt.com/docs/enterprise/plugin-management#reconnect-or-change-github-access).
