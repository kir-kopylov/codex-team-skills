# Начать Здесь: Перевести Старую Установку

Этот путь нужен только компьютеру, где Team Skills раньше подключались локальной копией или фоновым обновлением. Переход выполняет агент локальными командами. Новый скачиваемый очиститель не используется.

## 1. Снимок Без Изменений

Применяй [проверку штатной CLI](codex-cli-preflight.md): при сломанной команде из PATH проверь уже установленный официальный CLI с тем же Codex home и профилем. Далее `codex` означает выбранный проверенный executable.

Сначала сохрани приватно и кратко опиши пользователю:

- результат `codex --version`, `codex plugin --help` и `codex plugin list --json`;
- точный тип регистрации marketplace (`marketplaceSource.sourceType` / `source_type`), source и ref. Git origin папки не доказывает Git-регистрацию; `source.source = "local"` у plugin внутри Git marketplace относится к другому слою;
- наличие в `~/.codex/config.toml` точного управляемого блока от `# BEGIN codex-team-skills managed block` до соответствующего `END`;
- наличие `~/plugins/team-skills`, `~/.codex/plugins/cache/codex-team-skills` и marketplace-файла;
- на Windows — задачу `Codex Team Skills Auto Update` и `%LOCALAPPDATA%\CodexTeamSkills`;
- на macOS — LaunchAgent `com.codex-team-skills.autoupdate` и `~/Library/Application Support/CodexTeamSkills`.

Не публикуй содержимое личных файлов, токены и абсолютный домашний путь.

## 2. Проверка Владения Перед Очисткой

Проверяй локальный marketplace даже при уже установленном plugin. Для каждого изменяемого объекта сначала докажи принадлежность:

- запись marketplace должна указывать на наблюдаемый локальный источник Team Skills и соответствующий manifest; чужой source или неоднозначный состав не заменять;
- управляемый блок должен иметь точные границы и содержать только marketplace `codex-team-skills` и plugin `team-skills@codex-team-skills`;
- `~/plugins/team-skills` должен быть обычным каталогом, а `.codex-plugin/plugin.json` внутри — иметь `name` = `team-skills`;
- cache удаляется только по точному пути `~/.codex/plugins/cache/codex-team-skills` после доказанной идентичности plugin;
- Windows-задача должна иметь точное имя `Codex Team Skills Auto Update`, а её действие — указывать внутрь `%LOCALAPPDATA%\CodexTeamSkills`;
- macOS plist должен иметь точный `Label` = `com.codex-team-skills.autoupdate`, а `ProgramArguments` — указывать внутрь `~/Library/Application Support/CodexTeamSkills`;
- каталог поддержки не должен быть ссылкой или reparse point; допустимы только доказанные файлы старого Team Skills updater.

Если имя, путь, границы, manifest, действие задачи или состав каталога не совпали, остановись без удаления и покажи расхождение пользователю. Не требуй наличия всех legacy-объектов: проверка владения нужна для найденных объектов, которые будут изменены.

Если marketplace содержит другие plugins, сохрани их записи и источник. Не вызывай удаление общего marketplace ради одного Team Skills. Исходный рабочий Git-каталог с незакоммиченными изменениями не удаляй и не меняй.

## 3. Сохранение До Любой Замены

Выполни [сохранение до замены](preserve-before-reconnect.md): сохрани вне удаляемых каталогов конфигурацию, затрагиваемые marketplace-метаданные и весь установленный пакет; прочитай копию обратно и проверь состав и SHA-256. Если `plugin list` не раскрывает `installedPath`, сохрани полный проверенный `preservation_set` по этой процедуре, не угадывая активную версию. Сохрани сведения о восстановлении. Отсутствие и точного пути, и полного проверенного набора даёт `BLOCKED_PRESERVATION` до первой изменяющей команды.

Для локального/разрабатываемого источника или просьбы сохранить расширение сравни содержимое с актуальным полным SHA удалённого `main`, зафиксированным вместе с manifest. Уже включённое расширение не требует повторного PR; отсутствующее нужно сохранить и определить его судьбу до замены. Резервная копия сама по себе не означает, что расширение будет работать в новой установке. Сними состояние исходного рабочего Git-каталога для последующей проверки неизменности.

Непосредственно перед изменением перечитай plugin/marketplace и проверь свежесть снимка и условно проверенного `main`. При расхождении обнови снимок и сравнение, не удаляя старую копию и не придумывая причину изменения версии.

## 4. Штатное Удаление После Сохранения

Только после проверки владения, резервной копии и свежести снимка выполни уже разрешённое переподключение без повторного согласования. Команды ниже относятся к подтверждённой отдельной регистрации `codex-team-skills`:

```powershell
codex plugin remove team-skills@codex-team-skills --json
codex plugin marketplace remove codex-team-skills --json
```

Отсутствующий объект допустим. Ошибка разбора конфигурации не разрешает массовое удаление: переходи к точечной проверке ниже.

## 5. Конфигурация Codex

Если штатная команда не удалила старую запись, работай только с `~/.codex/config.toml`. Должна существовать ровно одна пара точных границ `# BEGIN codex-team-skills managed block` и `# END codex-team-skills managed block`, а внутри — только секции marketplace `codex-team-skills` и plugin `team-skills@codex-team-skills`.

Сохрани резервную копию рядом с файлом, удали весь доказанный блок вместе с его границами и атомарно замени исходный файл. Остальной TOML сохрани байт-в-байт. При второй паре границ, незакрытом блоке, дополнительных секциях или ошибке записи остановись без удаления.

## 6. Marketplace JSON

Читай старый `~/.agents/plugins/marketplace.json` как `UTF-8` с допустимым BOM. Удали только запись с `name` = `team-skills`, если её source указывает на доказанный старый plugin.

Если в файле есть другие plugins, сохрани их без изменений. Результат запиши атомарно как `UTF-8 без BOM`. Перед заменой сохрани локальную резервную копию рядом с исходным файлом. Если JSON повреждён или source неоднозначен, остановись без удаления.

## 7. Подключение Штатного Marketplace

После доказанного удаления старых следов выполни:

```powershell
codex plugin marketplace add kir-kopylov/codex-team-skills --ref main --json
codex plugin add team-skills@codex-team-skills --json
```

Прочитай `codex plugin list --json` обратно: ожидаются Git-регистрация канонического репозитория, ref `main` и включённый plugin. Проверь сохранность нужного расширения и неизменность исходного рабочего Git-каталога по снимку. Сохрани резервные копии; несовпадение не исправляй повторным удалением.

Сохрани контрольную точку и выполни доступный безопасный перезапуск с продолжением проверки. Если такого способа нет, оставь `RESTART_PENDING` и назови одно ручное действие, не завершая процесс принудительно. В новой задаче проверь наличие `team-skills:razgrom-plana-na-naivnost`; CLI и файлы cache сами по себе не подтверждают новую сессию.
