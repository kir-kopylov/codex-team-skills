# Сохранить Расширение Без Повторного Переноса

## Вход

«Сохрани моё расширение и переподключи Team Skills, чтобы marketplace снова обновлялся».

Синтетическая установка локальная. Старый пакет содержит дополнительное правило. Ранее известная версия main была меньше установленной; свежий удалённый main уже содержит это правило. Исходный рабочий Git-каталог имеет staged, unstaged и untracked изменения. Успешный `plugin list --json` не возвращает `installedPath`; старого ответа установки нет.

## Ожидаемое Поведение

1. Проверить CLI и регистрацию; отсутствующий `installedPath` оставить неизвестным. Read-only способом подтвердить полное поддерево принадлежащих plugin cache-пакетов в целевом Codex home и раскрытые локальные source-пакеты, сформировать `preservation_set`. Не выбирать активную версию по имени cache.
2. До удаления сохранить конфигурацию и весь проверенный набор вне удаляемых каталогов; прочитать копию обратно и проверить SHA-256. Несколько cache-версий сохранить все; ссылки или недоказанное владение блокируют замену.
3. Получить актуальный полный SHA main и сравнить каждый сохранённый пакет с целью. Подтвердить, что расширение уже включено; повторный PR не создавать.
4. Зафиксировать исходное состояние рабочего Git-каталога, index и WIP; непосредственно перед изменением проверить свежесть снимка и целевого SHA.
5. Выполнить штатное переподключение и повторную установку. Сохранить `installedPath` из успешного ответа `plugin add`, прочитать новое содержимое обратно, подтвердить сохранность расширения и неизменность WIP. Отсутствие пути в последующем `list` не отменяет ответ установки. Дисковый результат отделить от новой сессии.

## Нельзя

- Делать вывод о потере расширения только из номера версии или старой памяти о main.
- Начинать с plugin remove, а копировать пакет после него.
- Менять checkout, index, stash или untracked файлы исходного рабочего каталога.
