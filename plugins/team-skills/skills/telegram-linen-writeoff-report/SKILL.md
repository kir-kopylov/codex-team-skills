# Telegram Linen Writeoff Report

## Ownership

Это доменный asset Надежды Симарзиной, упакованный в repo-контракт командных
skills. Текущий `owner` и авторство указаны в `skill.yaml`.

Skill сохраняет исходный рабочий замысел: отчет строится из Telegram Desktop
export, а не из пересказа. Если ожидаемый пакет scripts или references недоступен
в текущем запуске, Codex должен запросить его у пользователя, а не делать вид, что
может восстановить правила сам.

## Когда Использовать

Используйте skill, когда пользователь просит:

- сделать отчет списания белья по Telegram export;
- разобрать `messages.html` за период и посчитать белье по объектам;
- построить отчет по фамилиям отправителей;
- проверить спорные сообщения, подписи к фото, дубли или итоговые строки;
- нормализовать названия объектов и категории белья по правилам пакета.

Ожидаемый источник данных: Telegram Desktop export с файлом `messages.html`.

## Resource Gate

В начале работы проверьте, доступны ли ожидаемые ресурсы пакета:

- `scripts/build_linen_report.py`;
- `scripts/parse_telegram_export.py`;
- `references/linen_rules.md`;
- `references/object_aliases.md`;
- `references/examples.md`;
- `references/verification.md`.

Считайте эти файлы частью skill-пакета, даже если в текущей среде они не лежат в
repo рядом с `SKILL.md`. Их отсутствие в текущем запуске не доказывает, что они
никогда не существовали.

Если один или несколько ресурсов недоступны:

1. Остановитесь до построения отчета.
2. Назовите конкретно, каких файлов не хватает.
3. Попросите пользователя приложить недостающие файлы или указать путь к полному
   пакету.
4. Не пересоздавайте правила подсчета из памяти.
5. Не пишите новый парсер вместо ожидаемого `build_linen_report.py`, если
   пользователь явно не попросил сделать отдельную новую реализацию.

## Процесс

1. Найдите Telegram export folder и подтвердите наличие `messages.html`.
2. Проверьте период отчета: start и end должны быть явными датами; период
   считается включительно.
3. Пройдите `Resource Gate`.
4. Перед запуском отчета прочитайте `references/linen_rules.md` и
   `references/object_aliases.md`, если они доступны.
5. Запустите `scripts/build_linen_report.py` с `messages.html`, start и end.
6. Если пользователь просит отчет по фамилиям, добавьте режим `--group-by surname`.
7. По умолчанию верните отчет прямо в ответе Codex. Файл создавайте только по
   явной просьбе пользователя.
8. Если нужна проверка счета, используйте evidence output и покажите пользователю,
   какие сообщения влияли на спорные строки.
9. В конце добавьте блок `Спорные или непонятные места`, если есть неоднозначные
   подписи, дубли, итоговые сообщения или объект не удалось восстановить.

## Правила Подсчета

Базовые правила из исходного skill сохраняются как стартовая рамка, но
приоритет имеет `references/linen_rules.md`, если он доступен.

- Считать только запрошенный период, включительно по start и end.
- Считать только категории: `БП`, `СП`, `НП`, `МП`, `Пододеяльник`,
  `Простынь`, `Наволочка`.
- Слова `ноги`, `ножки`, `лапки`, `для ног` относить к `НП`, если reference не
  задает более точное правило.
- `МП` держать отдельной строкой, не смешивать с `НП`.
- `Без объекта` использовать только когда объект нельзя восстановить из блока
  сообщения.
- Короткие подписи к фото и follow-up сообщения считать продолжением только по
  правилам близости, отправителя и контекста из `linen_rules.md`.
- Если сообщение `итого` суммирует предыдущие детали, не удваивать счет.
- Не считать обсуждения, если они не вводят новую количественную запись.

## Нормализация Объектов

Перед отчетом прочитайте `references/object_aliases.md`. Не расширяйте aliases
по догадке в финальном отчете. Если встречается новый вариант объекта, покажите
его в спорных местах и предложите отдельное обновление reference после проверки.

Примеры исходной нормализации:

- `Общий фонд`, `общ фонд` -> `ОФ`;
- `Югозапад`, `Юго запад` -> `Юго-Запад`;
- `Юмашева` -> `Юмашева 6`;
- `Хохрякова 63 -46` -> `Хохрякова 63`.

## Формат Ответа

Если пользователь не попросил таблицу или файл, возвращайте отчет блоками по
объектам:

```text
Объект:
БП-0
СП-0
НП-0
МП-0
Пододеяльник-0
Простынь-0
Наволочка-0
```

После объектов добавьте totals, если они помогают проверке. В конце добавьте
`Спорные или непонятные места` или прямо напишите, что спорных мест не найдено.

## Антипаттерны

- Не строить отчет без `messages.html`.
- Не заменять отсутствующий package догадками Codex.
- Не считать скриншоты, пересказы или голосовые сообщения полноценной заменой
  Telegram export.
- Не смешивать `МП` и `НП`.
- Не прятать сообщения, где объект, категория или дубль спорны.
- Не добавлять raw приватные чаты, телефоны, ID аккаунтов или личные пути в repo.

## Логирование Сбоев

Перед выполнением прочитайте локальный `known-exceptions.yaml` как список уже
известных случаев и применяйте подходящее `do_next_time` без нового поиска.

Если пользователь поправил skill, tool/API/browser упал, нарушен режим работы,
пришлось искать workaround или skill сделал ложное предположение, запишите
приватную карточку в
`~/.codex/skill-runs/telegram-linen-writeoff-report/exception-log.jsonl`.

Пишите факты: что skill хотел сделать, что сделал, где сломался, какая
предпосылка была ложной и что сделать в следующий раз. Если поле неизвестно,
пишите `unknown`. Raw logs не коммитить.

## Definition Of Done

Задача закрыта, когда:

- `messages.html` найден и период явно задан;
- ожидаемые scripts и references доступны или пользователь получил точный запрос
  на недостающие ресурсы;
- отчет построен через ожидаемый script, если пакет доступен;
- категории и объекты нормализованы по reference;
- спорные места названы, а не замаскированы;
- финальный результат возвращен в chat или сохранен в файл только по просьбе.
