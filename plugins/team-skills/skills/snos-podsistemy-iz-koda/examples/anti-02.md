# Анти-Пример: Replacement Platform

## Вход

После команды «снести updater» предлагается сначала построить новый orchestrator, централизованную telemetry, repair daemon, rollback service и набор end-to-end тестов для старого updater.

## Ожидаемое Поведение

Codex останавливает расширение scope. Он возвращает уже принятое решение об удалении, формулирует минимальный остаточный контракт и отделяет действительно нужную одноразовую миграцию от нового постоянного runtime. Если новый канал доставки действительно нужен, это выносится в отдельное решение с собственным value gate.

## Нельзя

Нельзя делать удаление предлогом для replacement architecture. Нельзя сначала harden и тестировать механизм, который по утверждённому решению должен исчезнуть.
