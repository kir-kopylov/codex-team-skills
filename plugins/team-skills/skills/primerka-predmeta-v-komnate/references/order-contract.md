# Контракт заказа

## Обязательные параметры

| Поле | Значение |
| --- | --- |
| room_images | Одно или несколько доступных изображений одного помещения |
| target.item | Один предмет или однородная группа |
| target.operation | add или replace |
| counts.variations | N — число вариантов |
| counts.images_per_variation | M — число изображений каждого варианта |

Количество экземпляров target.quantity не умножает число файлов. Размещение target.location уточняется только при существенной неоднозначности.

## Опциональные параметры

- variation_mode: придумать варианты (auto_concepts) по умолчанию, взять описания (provided_concepts) или образцы товаров (product_references);
- design_goal: цель из запроса, по умолчанию «Сравнение вариантов»;
- variation_axes: форма, конструкция, материал, цвет, размер, деталировка или смешанный набор;
- constraints: габариты, бюджет, материалы, цвета, стиль, уход, безопасность и запреты;
- preserve: дополнительные элементы, которые нельзя менять;
- presentation_state: пустой, собранный, накрытый, включённый или другой явно заданный вид;
- view_priority: порядок исходных видов;
- generator.requested и generator.policy;
- output_location.

Если роль образца неоднозначна, уточните, нужна ли точная модель или стилевой ориентир, только когда это меняет результат.

Размеры и план помещения не являются входным барьером. При их отсутствии размещение остаётся приблизительным.

## Роли изображений

- anchor_room — направление взгляда, перспектива, геометрия и освещение конкретного результата;
- supporting_room — дополнительные сведения о том же помещении без права менять камеру;
- product_identity — конструкция конкретного предмета;
- style_reference — материал, цвет или настроение без заявления о точной модели;
- generated_identity — первый прошедший кадр варианта для согласования остальных кадров.

Один файл не должен неявно исполнять противоречащие роли. В запросе генератору роль каждого изображения записывается явно.

## Матрица кадров

Source view получает id v01, v02 и далее. Каждый итоговый кадр получает shot:

~~~text
v01-t01
v02-t01
v01-t02
v02-t02
~~~

По умолчанию при одном пригодном исходном фото первый кадр — общий вид (kind=overview), остальные — крупные планы видимых деталей (kind=detail). Каждый кадр создаётся отдельной генерацией с тем же source_view и новым take. Выберите одинаковую область детали для всех вариантов и подпишите её в label.

При нескольких пригодных исходных видах используйте реальные ракурсы по порядку. Когда M больше их числа, виды повторяются по кругу. Если пользователь заказал конкретное кадрирование, учитывайте его в назначении кадра. Поле kind необязательно в карточках с прежними кадрами без этой отметки.

Порядок source_views с ролью anchor уже должен учитывать view_priority. Непригодные для самостоятельного результата изображения получают роль supporting и не входят в круг камер.

Основа имени файла строится как variant-shot, например `01-v02-t01`; исходное растровое расширение сохраняется при упаковке.

## Generator policy

- auto — пользователь не требовал конкретный генератор;
- preferred — допустима раскрытая замена;
- strict — при неподтверждённом совпадении генерация и упаковка прекращаются.

version_fulfilled=true допустимо только при доступном подтверждении фактического генератора. При отсутствии доказательства используется null, а не предположение.

actual_name обязателен для любой завершённой серии. actual_version может оставаться null, если инструмент не раскрывает версию.

## Приватность

Рабочая карточка может использовать локальные пути, необходимые для текущей генерации. Переносимый пакет не включает исходные фотографии комнаты, фотографии товаров или абсолютные пути. В командный repo попадают только синтетические примеры.

В переносимых промптах используйте роли и id изображений, а не локальные пути. Сборщик прекращает упаковку, если путь остался в любом экспортируемом тексте.
