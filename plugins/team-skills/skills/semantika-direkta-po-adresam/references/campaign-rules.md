# Правила Раскладки Кампаний (лист «Кампании»)

Лист строится скриптом детерминированно из масок с вердиктом «в кампанию». Это черновик структуры для заливки в Директ, не готовая кампания: ставки, объявления и бюджеты — вне рамок skill.

## Оси

- **Кампания** = город × тип спроса: `Поиск — {Город} — Гео` (все гео-группы) и `Поиск — {Город} — Ядро и спрос` (остальные).
- **Группа объявлений** = один интент: для гео — один гео-кластер (`C1`, `C2`…), для остальных — одна группа спроса (`ядро`, `b2b`, `цена`…). Правило «1 группа = 1 интент» держит релевантность объявления запросу и спасает от статуса «мало показов» при дроблении мельче.

## Кросс-минусовка

Группы одной кампании не должны конкурировать за один запрос. Скрипт для каждой группы объявлений собирает токены-дифференциаторы сиблингов: стем встречается в масках другой группы той же кампании и не встречается в своих → кандидат в кросс-минусы группы (до 10, по алфавиту). Общие токены ядра STR (квартира, посуточно, снять, аренда, город) и предлоги исключены — они не различают группы.

Кросс-минусы в листе — колонка на группу; при заливке в Директ вносить их как минус-фразы на группу объявлений. Список детерминированный, но грубый: перед заливкой просмотреть глазами — эвристика может предложить лишнее (безопасно убрать) или пропустить редкий пересекающийся токен.

## Точечные исключения

`campaign_overrides` в config — готовые строки листа для случаев, которые не ложатся в оси (например, отдельная кампания под событие с датным включением). Скрипт добавляет их в конец листа как есть.
