# Хороший Пример: Старый Custom Prompt

## Вход

«У меня есть старый файл custom prompt, но после обновления Codex его нет в меню. Сделай, чтобы привычный сценарий снова запускался быстро. Короткое имя хочу `Fast_Migration`.»

## Ожидаемое Поведение

Skill сначала фиксирует наблюдаемую целевую поверхность и пользовательский scope, а если они неясны — задаёт по одному вопросу. Затем проверяет, поддерживается ли custom prompt в текущем runtime, и фиксирует безопасную пробу его поведения. Если прежний формат не поддерживается, до записи нормализует имя в `fast-migration`, проверяет формат и длину, показывает итоговое имя, а для CLI/IDE — вызов `$fast-migration`, затем проверяет целевой path и другие skills с тем же `name`. Занятый другим поведением файл не перезаписывает: возвращается к выбору имени, снова показывает новое имя и, для CLI/IDE, новый `$вызов`, затем повторяет collision-check. Для свободного имени создаёт эквивалентный пользовательский skill в `$HOME/.agents/skills/fast-migration/SKILL.md`; на Windows пишет UTF-8 без BOM и запускает validator через `python -X utf8`. Исходный файл без согласия не удаляет. После этого отдельно проверяет или помечает как неподтверждённые применимые для выбранной поверхности обнаружение, фактический вызов и сохранение поведения на исходной пробе.

## Нельзя

Записывать `Fast_Migration` как имя папки или поле `name`, перезаписывать чужой skill при совпадении имени, создавать skill в недокументированном path или с BOM, считать `UnicodeDecodeError` доказательством невалидности, удалять старый файл или утверждать, что миграция сработала без проверки запуска на выбранной поверхности.
