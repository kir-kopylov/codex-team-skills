# Domain Playbook

## Что Нельзя Потерять

Сохраните дату отчёта, точный период, часовой пояс, номера заявок, объекты, валюты и время чтения eHous. Сопоставьте отчёт и базу в обе стороны по номеру заявки, затем проверьте объект, даты, ночи, статус и канал. При запросе «это вся выручка?» подтвердите охват обеих сторон, включая применимый архив. Если начало периода неизвестно, сверяйте предъявленные строки с явной пометкой о неполноте.

Для Google-таблицы, доступной лишь через приложенную выгрузку, назовите версию копии и границу проверки формул. Сопоставьте суммы на одинаковом основании и с одинаковым периодом. Банковская выписка или отчёт о выплате устанавливают перечисление, если есть связь с заявкой либо подтверждённое распределение общей выплаты.

## Что Надо Обезличить

Профиль подключения, путь к базе, учётные данные, реальные адреса, номера заявок, исходные отчёты, выписки и коммерческие ставки держите вне библиотеки. Читающий запрос выбирает только поля для сверки, без данных гостей и комментариев. Примеры используют вымышленные данные.

## Interface Mechanics

Используйте разрешённое подключение и PowerShell 7 с .NET 8 и доверенным клиентом Firebird 10.3.4. Считыватель открывает одну транзакцию только для чтения и откатывает её. Подходит существующий приватный профиль проверки броней. Передайте абсолютный путь через `-ConfigPath` или настройку `EHOUS_BOOKING_CONFIG`. Без них ищется `~/.codex/ehous-booking.json`.

Профиль указывает `DataSource`, `Database`, `UserID`, `ClientDllPath`, `PasswordIniPath`, `PasswordIniSection`, `PasswordIniKey`. Дополнительно можно указать `Port` и `Charset`, по умолчанию 3050 и WIN1251. Относительные пути разрешаются относительно самого профиля. Значение ключа читается из одной секции существующего файла настроек внутри процесса. Используйте учётную запись с разрешённым чтением.

Пример команды для вымышленных объектов.

```powershell
& '<папка навыка>/scripts/read-ehous-revenue.ps1' -From '2030-06-01' -Through '2030-06-20' -ApartmentId 101,102 -BookingId 100001,100002 -ConfigPath '<абсолютный путь к приватному профилю>'
```

`-Through` включает указанную дату. `-ApartmentId` задаёт объекты для проверки полноты, а необязательный `-BookingId` добавляет номера из отчёта даже за пределами этих объектов и дат. Используйте оба списка, когда нужно найти лишние и пропущенные заявки. Считыватель читает `ZAIVKA` и `ARH_ZAIVKA` и сохраняет происхождение каждой строки. Дополнительные начисления из `ZAIVKA_PLUS` и `ARH_ZAIVKA_PLUS` возвращаются отдельно. `database_time` содержит время по часам базы. Часовой пояс установите по подтверждённому правилу отчёта.

При неизвестном начале периода передайте только нужные номера через `-BookingId` и дату `-Through`. Такой запрос сверяет предъявленные строки. `inventory_queried=false` показывает, что весь период по объектам не запрашивался. `unknown_apartment_ids` перечисляет номера объектов без совпадения в текущем справочнике. Установите их принадлежность по источникам, прежде чем подтверждать охват.

- `IN_D`, `OUT_D`, `IN_TM`, `OUT_TM`, `DC`, `SOST`, `OTBOY` дают даты, число дней и признаки статуса. Для учёта ночей подтвердите состав периода и факт начисления. Отмена на более позднюю дату требует проверки версии на срез.
- В проверенной схеме `ZAIVKA.SM` вычисляется как `S × DC + S_DOP`. Перед учётом выделите аренду и проверьте, что вошло в надбавки. Штрафы, залоги, возвраты, авансы и ночи после среза показывайте отдельно.
- `REKLAMA.PER` и `REKLAMA.SM` показывают текущие настройки процента и фиксированной составляющей, а `SM_RAS` — вычисленное поле комиссии по правилам eHous. В проверенной схеме есть деление `per / 100` и фиксированная составляющая за дни. Из формы числа или совпадения сумм нельзя установить единицы ставки, полный состав комиссии и удержание площадкой. Нужен источник, относящийся к конкретной заявке и дате. При фиксированной составляющей, скидках или иной базе передавайте подтверждённую сумму комиссии за период.
- `D_REG` и `D_USR` дают регистрацию и последнее изменение. Для старого среза используйте датированную выгрузку или восстановленные по источникам поля заявки. Снимок текущего состояния и наличие архива сами по себе не подтверждают полноту прошлого среза.

## Recovery And Edge Cases

Считыватель прекращает работу при превышении 500 записей в одной таблице заявок. Разбейте запрос по объектам или датам и проверьте пересечения при объединении. Если `extra_charges_complete=false`, покрытие дополнительных начислений неполное. При отсутствующем архиве, ошибке подключения или несовместимой схеме продолжите по доступной датированной выгрузке и покажите границы охвата.

Сохраните дубли и спорные строки для проверки. При несовместимых датах, неизвестной комиссии или отсутствии доказательства исторической версии оставьте зависимые суммы неизвестными. Подтверждённая выплата по доступному документу остаётся видимой. Сначала установите основание каждого поля, затем передайте проверенные значения в [расчёт](ehous-revenue-input.md).
