# Вход И Результат Сверки eHous

Откройте источники и перенесите доказанные значения в JSON по [примеру](../assets/ehous/revenue-example.json). Сохраняйте точный указатель на строку или документ в `source`. Снимок читающего запроса даёт исходные поля для этой нормализации. Расчёт проверяет переданные связи, период и арифметику. Достоверность документов устанавливается при их чтении.

```text
python3 <абсолютный-путь-навыка>/scripts/reconcile_ehous_revenue.py <абсолютный-путь-входа>
```

Скрипт читает вход и выводит JSON. Для неизвестного используйте `null`. Деньги и ставки передавайте десятичными строками без разделителя тысяч и экспоненты. Даты записывайте в формате `ГГГГ-ММ-ДД`, время — в ISO с секундами. Все даты и часы должны относиться к согласованному отчётному часовому поясу. Валюта — трёхбуквенный код.

## Разделы Входа

| Раздел | Содержание |
| --- | --- |
| `schema_version` | Число `1`. |
| `scope` | `objects` — выбранные объекты, `from` — начало или `null`, `through` — дата среза включительно, `timezone`, `decimals` и `rounding` (`half_up` или `half_even`). |
| `ehous` | `source`, `read_at` — время чтения, `as_of` — доказанная дата снимка или `null`, `coverage_source` — доказательство полного охвата объектов и периода или `null`, `rows` — заявки. Для старого среза текущий запрос сам по себе не даёт `as_of` и `coverage_source`. |
| `report` | `source` — отчёт и его версия, `coverage_source` — подтверждение охвата или `null`, `rows` — строки. Необязательное `limitations` фиксирует, например, доступность только копии без проверки живых формул. |
| `payments` | Платёжные документы и доказанные распределения. Пустой список допустим, когда подтверждения недоступны. |

Каждая заявка и строка отчёта содержит `id`, `object`, `currency`, `source`. Сопоставимые поля `channel`, `status`, `arrival`, `departure` и `nights` добавляйте по источникам. `nights` относится ко всей брони. Используйте одинаковые обозначения для одних и тех же объектов и статусов.

**Заявка eHous.** Обязательны `eligible` и `full`. В `eligible` запишите `true` для подтверждённого начисления аренды, `false` для доказанного исключения и `null` при неизвестном статусе. `full` содержит сумму всей брони, её основание и источник либо `null`.

- Для подтверждённой суммы за выбранный период используйте `accrual`. Для подтверждённых цен по ночам используйте `nightly` с полями `basis`, `source` и `dates` (дата → цена). `full` и `accrual` имеют поля `amount`, `basis` (`gross`, `net` или `null`) и `source`. При продолжении проживания сумма всей брони годится для начисления только при полном попадании брони в отчётное окно. Для равномерной ставки сначала подтвердите правило и укажите подтверждённую цену каждой нужной ночи. При неполных данных остаётся неизвестная сумма.
- `edited_at` сохраняет время изменения текущей записи. Если состояние на срез восстановлено отдельно, укажите `history` с полями `date` и `source` и внесите в заявку именно восстановленные даты, статус, суммы и прочие поля. Для датированного полного снимка достаточно подтверждения в `ehous.as_of` и его источнике.
- `commission` содержит `kind` (`amount` или `rate`), `value`, `source` и для ставки явное `unit` (`percent` или `fraction`). Источник должен связывать удержание со строкой, датой, валютой и начислением за выбранный период. Для чистой суммы сохраняйте `basis: net`. Подтверждённая сумма самой комиссии может дать исходное начисление сложением. Неизвестные единицы или неподтверждённое основание оставляют зависимый итог неизвестным.
- Для подтверждённого правила конкретной строки можно переопределить округление через `rounding` с полями `decimals`, `mode`, `source`. Скрипт округляет начисление и комиссию по строке до суммирования. `other_charges` содержит отдельные записи с `kind`, `amount`, `source` и необязательным `date`.

**Строка отчёта.** Укажите `amount`, `basis` (`gross`, `net` или `null`) и `period` (`scope` для начисления за выбранный период, `full` для всей брони либо `null`). Устанавливайте основание по отчёту, а не по совпадению суммы с предполагаемой ставкой.

**Платёж.** Обязательны `id` (устойчивый идентификатор операции), `date`, `recipient`, `currency`, `amount`, `source`, `kind` и `allocations`. В `kind` укажите `rent`, `advance`, `deposit`, `refund`, `penalty` или `other`. Сумму аренды распределяйте только по подтверждённым связям. Каждая часть содержит `booking_id`, `object`, `amount`, `source` связи с арендой за нужный период. Сумма частей ограничена документом. Повтор одного платежа остаётся спорным, а платежи после среза показываются отдельно.

При полном подтверждении перечислений по заявке до даты среза укажите в заявке `payout_coverage_source`. Это может включать установленное отсутствие выплаты. Если доказана только часть, покажите её с открытым полным итогом. Расчётное допущение о получении начисленного показывайте отдельным сценарием.

## Что Показать В Ответе

- Время чтения eHous, дату среза, охват и версию отчёта. Покажите счётчики совпадений, отсутствующих заявок, лишних и спорных строк (`counts`).
- По заявке покажите исходную сумму и основание, полную стоимость, число учитываемых и будущих ночей, начисление до комиссии (`before_commission`), комиссию, расчёт после неё (`after_commission`), подтверждённое перечисление (`confirmed_payouts`) и источник каждого значения. Сравнивайте сопоставимую сумму отчёта с её основанием. Разница с расчётом после комиссии (`report_minus_after`) показывает, на сколько отчёт отличается от чистого начисления. У суммы отчёта до комиссии часть этой разницы может быть самой комиссией.
- Сведите суммы по объектам и валютам. Для каждого итога `amount` — полная сумма при подтверждённом охвате, `known_amount` — доказанная часть, `unknown_rows` — строки без суммы, `complete` — полнота. Если итог неизвестен, оставьте его открытым и укажите подтверждённую часть. Штрафы, прочие начисления, несопоставленные и последующие платежи показывайте отдельно.
