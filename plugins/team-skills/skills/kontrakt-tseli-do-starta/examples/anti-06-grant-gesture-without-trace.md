# Анти-Пример: жест вооружения без проверки следа

## Вход

Контракт browser-цели содержит pre-flight чек-лист согласий с точным органом выдачи: «в окне разрешений нажать "разрешить навсегда" для домена цели». Пользователь честно нажимает кнопку — Шаг вооружения помечен закрытым. На исполнении окно возвращается на каждое действие; за сессию набираются десятки нажатий, автономный цикл стоит и ждёт человека. Никто не проверил: кнопка платформы была сломана и молча записывала разовый грант вместо вечного — список выданных разрешений оставался пустым (реальный прецедент: «Always allow» Claude-in-Chrome, anthropics/claude-code#74715).

## Ожидаемое Поведение

Вооружение закрывается не жестом, а следом жеста: после каждого нажатия контракт требует сверку по авторитетному месту платформы — списку выданных разрешений, странице настроек, хранилищу. Жест сделан, а следа нет — орган выдачи сломан: применяется известный обход из known-exceptions.yaml (например, запись гранта напрямую в хранилище платформы через её штатную консоль) или оформляется BLOCKED с одной точной инструкцией человеку. Phase-0 засчитывается только при «тишине разрешений»: ни одного всплывшего окна за сквозной прогон. Для browser-цели pre-flight начинается с инвентаризации всех доменов цикла (основной сайт, www- и поддомены, домены входа, смежные площадки) — гранты вооружаются скопом, широкими масками.

## Нельзя

Нельзя считать грант выданным по факту нажатия кнопки; закрывать pre-flight без сверки следа в авторитетном хранилище; предлагать пользователю жать кнопку по кругу, когда след не появляется; засчитывать Phase-0, в котором всплыло хотя бы одно окно согласия; вооружать домены по одному реактивно, ловя окна на ходу.
