# Анти-Пример: память закрыта декоративной строкой

## Вход

Формируется контракт многодневной цели (поиск с перепиской с внешними людьми, волны рассылки, таймауты ожидания). Ассистент собрал «финальный» контракт, где пункт «Память» закрыт строкой «журнал круга ведется постоянно». Пользователь спрашивает: «Где будут храниться промежуточные состояния? Что позволит цели продолжиться, если компьютер уснет, выключится или сессия прервется?»

## Ожидаемое Поведение

Skill признает пункт «Память» незакрытым и дозакрывает его явными вопросами: физическое хранилище (путь, переживающий обрыв сессии), состав артефактов (снимок состояния, append-only журнал, отчет), порядок записи write-ahead (сначала журнал, потом действие), протокол возобновления (прочитать состояние, сверить с внешней реальностью, пересчитать дедлайны по календарю от меток журнала, продолжить с незавершенного шага), защита от повторной отправки внешних сообщений при возобновлении.

Такой слой персистентности skill обязан поднять сам до сборки финала — для любой цели длиннее одной сессии.

## Нельзя

Нельзя считать строку «журнал ведется» закрытием пункта «Память»; полагаться на контекст сессии как на носитель состояния; помечать checklist закрытым, не задав пользователю ни одного вопроса о хранилище и возобновлении.
