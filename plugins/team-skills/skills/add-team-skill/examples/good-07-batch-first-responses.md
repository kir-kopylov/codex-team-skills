# Хороший Пример: Пакет Первых Ответов

## Вход

Пользователь пишет: «Проверь первые ответы всех изменённых skills перед PR».
В рабочем scope три существенно изменённых skill; у одного из них изменён
только `known-exceptions.yaml`, а общая политика запуска не менялась.

## Ожидаемое Поведение

Codex определяет охват из трёх skills, включая изменение только
`known-exceptions.yaml`, и до запусков приватно фиксирует для каждого источник
фразы, один-три наблюдаемых критерия, запрещённое поведение,
SHA проверенной базы, полный repo-relative список обязательных источников,
фактически загруженные источники и обезличенный digest их точного состояния.
`known-exceptions.yaml` входит в обязательный список каждой из трёх строк,
даже если изменён только у второй; если любой агент загрузил один `SKILL.md`,
строка получает `BEHAVIOR_PROBE_BLOCKED`, а fingerprint не открывает commit.
До этого Codex без пропусков классифицирует полный diff каждого target.
Полный снимок сначала получается fail-closed объединением committed, staged и
unstaged tracked-файлов с untracked-файлами. Слои сравниваются независимо:
путь из branch commit или index не исчезает, даже если текущие worktree-bytes
вернулись к базе. Поэтому новый ещё не staged `agents/openai.yaml`,
`skill.yaml`, reference или example тоже попадает в охват; список, построенный
только по одному `git diff`, даёт `BLOCKED`. База сначала подтверждается как
полный exact commit OID; значения `--cached`, `--quiet`, ref или сокращённый
SHA дают `BLOCKED`, а не становятся опциями Git.
Изменённые `agents/openai.yaml` и `skill.yaml` всегда входят в точные пути
`scope_reason` и `required_source`; новый example можно исключить только после
доказательства, что он не является источником фразы или критериев этой строки.
Общая причина «skill изменён» и молчаливо потерянный путь дают `BLOCKED`.
Каждый путь глобального снимка назначен одной или нескольким строкам либо
занесён в `batch_excluded_source` с доказательством. Полноту этой карты,
содержимое путей и основания исключений связывает приватный
`batch_scope_fingerprint`; путь вне карты не позволяет открыть commit.
Для кандидата PR окончательный scope точечно staged до живых проб. Codex
сохраняет `head_oid`, выбранный `CREATE` или `AMEND`, точный ожидаемый список
parents, `index_tree_oid = tested_tree`, отсутствие unmerged и entries
`HEAD`/index/worktree каждого пути. Поэтому замена только staged bytes при
прежних path set и worktree hash аннулирует пакет.
Отдельный
приватный keyed digest
привязывает результат к источнику и точной фразе, упорядоченным критериям и
запрещённому поведению. `draft` запускается явно, остальные skills —
естественными фразами. Каждый первый ответ проверяется в отдельном свежем
контексте без критериев и соседних результатов. Для строки, способной менять
Git или внешнюю систему, Codex использует одноразовую копию точного target без
доступа к настоящему remote; общий worktree не меняется.

Внешний реальный пакет включает `add-team-skill`. Его внешняя строка загружает
точный кандидат и даёт ему внутренний одноразовый fixture той же базы. Во
внутреннем diff есть два других существенно изменённых skill и нет
`add-team-skill`. Кандидат вычисляет обе внутренние строки и запускает их
независимо. Это второй и последний уровень: внутренние строки не создают
третьего пакета. По первому ответу кандидата внешняя строка получает
`BEHAVIOR_PROBE_PASS`, `BEHAVIOR_PROBE_FAIL` или `BEHAVIOR_PROBE_BLOCKED`, после
чего внешний пакет в любом случае продолжает остальные строки реального
охвата.

Вторая строка получает `BEHAVIOR_PROBE_FAIL` с классом `NOTICE_ONLY`. Codex всё
равно проверяет третью строку, затем исправляет только второй skill и повторяет
его пробу в новом контексте. Commit открывается лишь после трёх актуальных
`BEHAVIOR_PROBE_PASS`. В summary для PR остаются только публичный охват,
счётчики и класс сбоя; сырые фразы, критерии и ответы остаются приватными.
Перед commit Codex заново сверяет базу, глобальную карту, список источников,
digest target и приватные digests пакета, охвата и контракта каждой строки.
Digest охвата включает
Git mode, content hash или маркер удаления каждого changed path и
доказательство для каждого исключённого пути. Поэтому смена `100644` на
`100755`, изменение содержимого исключённого example или основания его
исключения после пробы аннулирует строку. Symlink может быть учтён в batch, но
не загружается и не передаётся target-агенту. Любое изменение фразы, порядка
или содержания критериев либо запрещённого поведения аннулирует строку. Если
база
продвинулась, он по её diff и пересчитанному охвату повторяет только затронутые
строки, а незатронутые перепривязывает к новому SHA после доказательства
неизменности row-level entries и контракта; новые глобальные `head_oid`,
`expected_parent_oids` и `index_tree_oid` подтверждаются поздним Git-гейтом и
входят в новые base-bound fingerprints. Равенство старого и нового digest при
разных SHA не требуется. Изменение
общего поведенческого контракта аннулирует весь пакет. В PR не попадает ни один
из приватных fingerprints.

После commit прежняя проба переносится только по точному receipt: parents
совпадают с заранее сохранёнными для выбранного перехода — у `CREATE` это
будущие parents от `HEAD`, у `AMEND` parents заменяемого commit. Commit tree
равен precommit `index_tree_oid` и `tested_tree`, новый index содержит тот же
tree, postcommit `HEAD`/index entries равны precommit index entries, worktree
entries неизменны, а полный status чист. Иначе commit считается новым
кандидатом и требует новой пробы.

## Нельзя

Нельзя проверить только один удобный skill, остановить сбор дефектов после
первого `FAIL`, переиспользовать контекст, раскрыть сырые запросы или считать
частичный либо устаревший пакет основанием для commit, push или PR. Нельзя
считать `PASS` актуальным только по совпадению имени skill или старого SHA
базы, не доказав обязательную загрузку `known-exceptions.yaml`, покрытие
остальных обязательных источников, полный учёт каждого изменённого пути и
точное состояние
фактически загруженных источников. Нельзя
терять новый untracked-файл до staging или считать совпадение списка путей
доказательством неизменности их содержимого и оснований исключения. Нельзя
проверять worktree, если index хранит другие bytes, или переносить `PASS` на
commit без совпадения parents и точного `tested_tree`. Нельзя
оставлять путь глобального снимка вне `batch_attribution` и
`batch_excluded_source` или переиспользовать старый `batch_scope_fingerprint`.
Нельзя
использовать рабочий target пользователя как песочницу живой пробы.
Нельзя передавать строке `add-team-skill` исходный diff с ней самой и считать
бесконечный вложенный пакет нормальной проверкой. Нельзя разрешать третий
уровень вложенности или считать внутренний fixture статусом всей внешней
строки без отдельной оценки первого ответа кандидата.
