# Хороший Пример: Draft От Коллеги

## Вход

Пользователь пишет: "Коллега из команды дала мне свой `SKILL.md`. Хочу добавить его в общую библиотеку, сохранить авторство и понять: добавить отдельно или интегрировать в похожий skill."

## Ожидаемое Поведение

Codex читает переданный draft, проверяет похожие skills в repo и сначала решает, есть ли самостоятельные входы, результат, triggers и проверки. Если draft усиливает существующий author workflow, Codex интегрирует его туда как checklist, example или reference, а не создает дубль. В `skill.yaml` он оставляет подтвержденного maintainer-а в `owner`, добавляет автора исходного вклада в `authors`, описывает источник в `source_asset`, обновляет examples и запускает `python3 -m pytest`.

## Нельзя

Нельзя добавлять отдельный skill только ради авторства, если в repo уже есть канонический skill для этой задачи. Нельзя придумывать GitHub handle автора, копировать приватные пути к draft-файлу или публиковать raw-контекст. Нельзя терять имя автора при интеграции вклада в существующий skill.
