# Хороший Пример: SIP-Тайм-Аут До Авторизации

## Вход

Пользователь сообщает: «SIP-клиент отправляет `REGISTER`, затем получает
timeout. Проверь, виноват ли пароль». В свежем очищенном журнале есть исходящий
`REGISTER`, но нет входящего SIP-ответа `401`, `403`, `407` или `200`.
Пользователь запретил менять credentials и сетевые настройки.

## Ожидаемое Поведение

Codex не объявляет пароль причиной: наблюдение ещё не достигло слоя
авторизации. Он формулирует:

```text
Факт: исходящий REGISTER виден, входящий SIP-код не наблюдался.
Пока неизвестно: запрос потерян по пути, ответ потерян на обратном пути или
удалённая сторона молча отбросила пакет.
Две проверяемые причины:
A — клиент не отправляет пакет в фактический сетевой интерфейс.
B — пакет выходит из клиента, а ответ не возвращается.
Один безопасный опыт: при неизменной конфигурации сопоставить один новый
REGISTER с локальным сетевым наблюдением исходящего пакета.
Если A: в интерфейсе пакет отсутствует.
Если B: в интерфейсе пакет присутствует, но ответ отсутствует.
Когда остановиться: один короткий цикл; не менять пароль, маршрут и transport.
```

Если для сетевого наблюдения нужны дополнительные права, Codex даёт одну
инструкцию пользователю и возвращает `blocked`, а не запускает другой опыт.

## Нельзя

Нельзя писать «неверный пароль» без ответа слоя авторизации. Нельзя одновременно
менять transport, порт, маршрут и credentials. Нельзя считать TCP-connect
доказательством SIP-регистрации или рабочего звонка.
