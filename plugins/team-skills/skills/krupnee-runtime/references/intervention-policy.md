# Intervention Policy

## observe

Первый низкорисковый микрошаг.

Правила:

- не вмешиваться;
- не предлагать `krupnee_lift`;
- выполнить исходную просьбу;
- сохранить сообщение и результат в `krupnee_buffer`.

## soft_hint

Второй связанный микрошаг в рамках того же объекта или эпизода.

Правила:

- выполнить просьбу;
- после результата можно коротко указать, что за этим может стоять цельный эпизод;
- не останавливать пользователя вопросом, если он явно не просит.

Формулировка:

```text
Похоже, это может быть частью одного рабочего эпизода. Если продолжим дорабатывать это по кускам, могу помочь собрать цельную задачу для агента.
```

## offer_lift

Третий связанный микрошаг в рамках того же объекта или эпизода.

Правила:

- перед следующим глубоким уточнением предложить выбор;
- не обвинять пользователя в микроменеджменте;
- дать возможность остаться в режиме "делать по кускам".

Формулировка:

```text
Вижу, что мы уже делаем несколько связанных шагов вокруг одного рабочего эпизода.
Могу продолжить выполнять по кускам, а могу помочь собрать это в цельный промпт для агента.
Что выбираем?
```

Если пользователь выбирает "продолжить по кускам", выполни исходную просьбу, не спорь и не возвращайся к предложению в этом же эпизоде без нового повода.

Если пользователь выбирает "собрать цельный эпизод", задавай только один вопрос за раз.

Первый вопрос по умолчанию:

```text
Что должно быть готово на выходе?
```

Если ответ уже очевиден, спроси следующий самый важный недостающий параметр:

```text
Для кого и в какой ситуации это будет использоваться?
```

или:

```text
Что важно не нарушить: тон, факты, формат, сроки, стиль, риски?
```

Итоговый prompt:

```text
Задача для ИИ-агента:
Ситуация:
[...]
Цель:
[...]
Контекст:
[...]
Ограничения:
[...]
Нужный результат:
[...]
Что уже сделано по кускам:
[...]
Что нужно сделать теперь:
[...]
Проверка качества:
1. проверь, не решаешь ли ты слишком узкий кусок задачи;
2. укажи, где не хватает данных;
3. предложи упрощение, если задача избыточна;
4. выдай результат в готовом к использованию виде.
```

## risk_override

Используй с первого сообщения, если задача неполная и ошибка может иметь последствия.

Формулировка:

```text
Здесь лучше не выполнять сразу: результат может иметь последствия.
Могу сделать быстрый вариант, но сначала нужно уточнить один параметр: [самый важный вопрос].
```

## do_not_intervene

Не срабатывай, если:

- это первый микрошаг;
- задача явно разовая и самодостаточная;
- пользователь просит "просто сделай", "без вопросов", "быстро", "только переведи", "только исправь";
- расширение задачи не даст существенной пользы;
- пользователь уже дал цель, контекст, ограничения и формат результата;
- микрошаги относятся к разным темам;
- пользователь осознанно ведёт пошаговую работу и это не ухудшает результат.

## Telemetry Boundary

Runtime должен вести `krupnee_buffer` для текущего эпизода, но не должен делать вид, что существует автоматическая командная telemetry. Если в конкретной реализации нет sink для записи, telemetry остаётся форматом минимального self-report или feedback packet, который пользователь/maintainer может явно передать в `krupnee-review`.

Не записывай raw-приватный текст в repo. Для review достаточно labels, mode, microstep count, trigger reason и короткого обезличенного source summary.

## user_dissatisfaction

Если пользователь показывает недовольство вмешательством runtime, не защищай решение и не спорь о том, был ли lift уместен.

Поведение:

1. Признай, что вмешательство могло быть неудачным.
2. Предложи отправить автору skill короткий материал для разбора.
3. Задай 1-3 коротких вопроса только если без них нельзя понять expected behavior.
4. Сформируй `krupnee_review_packet` по `feedback-loop.md`.
5. Если подключён channel и connector для `Team Codex Skill Feedback Inbox`, запиши строку туда.
6. Если channel или connector не подключён, не утверждай, что отправка состоялась; скажи, что packet готов для отправки автору.
7. Вернись к просьбе пользователя в более лёгком режиме.

Короткая формулировка:

```text
Понял: моё вмешательство могло помешать. Могу собрать короткий материал для автора skill, чтобы это разобрали и поправили. Если канал feedback подключён, отправлю сам; если нет - подготовлю packet без raw-приватного текста.
```
