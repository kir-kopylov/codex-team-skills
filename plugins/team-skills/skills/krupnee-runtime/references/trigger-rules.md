# Trigger Rules

## krupnee_buffer

Веди короткое окно текущего эпизода:

```yaml
krupnee_buffer:
  recent_user_messages: []
  recent_agent_outputs: []
  suspected_shared_object: null
  suspected_goal: null
  microstep_count: 0
  coherence_score: 0
  risk_level: low # low | medium | high
  intervention_state: observe # observe | soft_hint | offer_lift | risk_override | do_not_intervene
```

Сбрасывай или разделяй buffer, когда пользователь переходит к другому объекту, цели, артефакту или рабочему процессу.

## Связанные Микрошаги

Считай сообщения связанными, если они относятся к одному и тому же:

- тексту;
- документу;
- коду;
- макету;
- письму или сообщению;
- клиентскому эпизоду;
- задаче;
- плану;
- артефакту;
- рабочему процессу;
- решению.

Типовые цепочки:

- "переведи" -> "сократи" -> "сделай теплее";
- "сделай список" -> "добавь критерии" -> "теперь оформи как инструкцию";
- "переделай промпт" -> "убери лишнее" -> "добавь условия срабатывания".

## Scoring

Оцени короткое окно связанных сообщений, а не одно сообщение изолированно.

- `+1` повторный микрошаг по тому же объекту;
- `+1` цель всё ещё не названа явно;
- `+1` контекст использования не назван;
- `+1` новый шаг исправляет, дополняет или переформатирует предыдущий результат;
- `+1` видно, что можно поручить агенту цельный рабочий эпизод;
- `+1` есть риск слабого результата без уточнения.

Решение:

- `0-1`: выполнить сразу;
- `2-3`: выполнить и, если уместно, дать `soft_hint`;
- `4+`: предложить `offer_lift`, если польза выше задержки.

Ограничение: если это первый микрошаг и риска нет, не предлагай lift даже при формально неполной постановке.

## Условия Для offer_lift

Предлагай переход к цельному эпизоду только если одновременно выполнены условия:

1. Есть минимум 2-3 последовательных микрошагa.
2. Они относятся к одному объекту, цели или артефакту.
3. Каждый новый шаг уточняет, правит, дополняет или переформатирует предыдущий результат.
4. Цельный рабочий эпизод можно предположить без сильной фантазии.
5. Ожидаемая польза от сборки цельного prompt выше, чем задержка от уточнения.

## Risk Override

Можно сработать с первого сообщения, если задача неполная и ошибка может иметь последствия.

Высокорисковые зоны:

- деньги;
- юридические последствия;
- конфликт;
- клиентская коммуникация;
- публичная публикация;
- отправка письма или сообщения;
- изменение данных;
- доступы;
- конфигурации;
- commit;
- push;
- pull request;
- запуск фоновой задачи;
- действия во внешних системах.

## Dissatisfaction Signals

Отдельно отслеживай сигналы недовольства именно вмешательством runtime, а не качеством обычного результата:

- "зачем ты это предложил?";
- "это мешает";
- "не надо было спрашивать";
- "ты опять полез со своим lift";
- "это не туда";
- "слишком тяжело";
- "просто сделай".

Если сигнал связан с `soft_hint`, `offer_lift`, `risk_override`, лишним вопросом или чрезмерным runtime-комментарием, переходи в feedback loop из `feedback-loop.md`.

Если пользователь просто недоволен переводом, текстом, кодом или иной обычной выдачей без связи с поведением `krupnee-runtime`, исправь результат обычным способом и не оформляй `krupnee_review_packet`.
