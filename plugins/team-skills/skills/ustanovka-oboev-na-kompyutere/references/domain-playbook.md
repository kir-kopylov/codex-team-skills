# Domain Playbook

## Что Нельзя Потерять

- Проверка компьютера и пользовательского сеанса до изменения.
- Выбранный исходник, постоянная копия с совпадающим SHA-256 и сохранённая прежняя настройка.
- Различие между успешным вызовом, обратным чтением активного пути и увиденным рабочим столом.
- Вписывание целого кадра для текстовых обоев, если пользователь не выбрал другое размещение.

## Что Надо Обезличить

Имена пользователей и компьютеров, личные пути, вложения, реальные изображения, скриншоты и журналы. В публичных примерах используйте условный компьютер и относительный файл.

## Interface Mechanics

В целевом PowerShell-сеансе прочитайте `$env:COMPUTERNAME`, `[Environment]::UserName` и сведения о сеансе доступным инструментом. Проверьте источник через `Get-Item -LiteralPath`, копируйте через `Copy-Item -LiteralPath`, сравните `Get-FileHash -Algorithm SHA256` до и после копирования. Выбирайте постоянную папку через системный путь `MyPictures`, а не угадывайте имя профиля. Избегайте перезаписи существующих файлов.

Для одного общего фона применим Unicode-вызов `SystemParametersInfoW`. По [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow): `SPI_SETDESKWALLPAPER = 0x0014` (20) задаёт фон, `SPI_GETDESKWALLPAPER = 0x0073` (115) читает его путь; для записи флаги `SPIF_UPDATEINIFILE | SPIF_SENDCHANGE = 3` сохраняют настройку и рассылают уведомление. **115 не обновляет фон**, это только чтение. Для чтения передайте буфер `StringBuilder` и его ёмкость; проверяйте возвращённый `bool`, при ошибке — `Marshal.GetLastWin32Error()` с объявлением `SetLastError=true`. Для записи передайте полный путь строкой и `uiParam=0`; для чтения — `fWinIni=0`.

Объявляйте отдельные сигнатуры записи со строкой и чтения с `StringBuilder`, обе с `CharSet.Unicode` и `EntryPoint="SystemParametersInfoW"`. Не вызывайте функцию через `rundll32`: типы аргументов этой функции требуют корректного объявления. Сам по себе успешный `SET` не заменяет последующий `GET` и сравнение пути.

В использованной Windows-процедуре режим «Вписать» задавался строковыми значениями `WallpaperStyle=6`, `TileWallpaper=0` в `HKCU:\Control Panel\Desktop` перед применением фона. Это рецепт для текущего пользователя, не способ изменить удалённый или чужой сеанс. Сначала сохраните исходные значения и проверьте итоговое размещение; при неподтверждённом соответствии используйте доступные настройки «Персонализация → Фон». Другие режимы не вычисляйте по аналогии. Для нескольких мониторов с разными фонами используйте соответствующие настройки Windows или [IDesktopWallpaper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idesktopwallpaper).

## Recovery And Edge Cases

- Именованный компьютер не совпал: никакой записи на текущем; сначала доступное авторизованное подключение к цели, при его отсутствии — один запрос доступа.
- Путь другой ОС или только видимое в чате превью: это ещё не доступный файл. Ищите только в доступных вложениях и папке задачи; если точного изображения нет, попросите файл.
- Файл есть, но вызов отвергнут или формат не применился: сохраните ошибку, используйте поддерживающий файл интерфейс Windows. Не подменяйте изображение и не называйте попытку успехом.
- Путь вернулся пустой или другой: установка не подтверждена. Если Windows создала копию, установите её соответствие выбранному изображению; не считайте любое значение достаточным.
- Настройки частично изменились: восстановите затронутые значения и прежний фон, проверьте результат восстановления. Не обещайте откат без обратного чтения.
- Удалённый сеанс скрывает фон: прочитанная настройка подтверждает конфигурацию, а не видимость на физическом экране. Не меняйте параметры удалённого доступа без отдельного поручения.
