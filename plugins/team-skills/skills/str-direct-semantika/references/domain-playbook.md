# Domain Playbook

Механика сбора частот в Яндекс.Вордстате через браузер пользователя. Всё, что здесь помечено `[requires recheck]`, калибруется на первом реальном прогоне и заменяется фактом.

## Что Нельзя Потерять

- `wordstat-progress.jsonl` — append-only журнал снятых частот в папке проекта (НЕ в папке skill). Каждая частота дописывается сразу после снятия; обрыв сессии ничего не теряет — рестарт читает журнал и продолжает с несобранных масок.
- Ручные правки в книге (вердикты, решения по спорным минусам, комментарии) — книга их единственный носитель. Пересборка `build` без `--force` запрещена скриптом; дозаливка только `merge` (сам делает sidecar-бэкап).
- Мусорные хвосты, увиденные при сборе частот, — записывать в журнал сразу (поле `tails`), не «потом»: второй раз в выдачу никто не пойдёт.

## Что Надо Обезличить

- В примеры, репо и известные исключения не переносить реальные города, адреса, названия ЖК и частоты клиента — только «Город N», «ул. Примерная 1», «кластер C1».
- region_id и откалиброванные пороги — рабочие данные книги, в репо они не публикуются.

## Interface Mechanics

1. Открыть `wordstat.yandex.ru`. Редирект на `passport.yandex.ru` = нет сессии → стоп, логинится пользователь сам (skill не вводит пароли).
2. Выставить регион: кнопка выбора регионов → город из config. Записать `region_id` из URL/интерфейса в config при первом прогоне `[requires recheck]`.
3. По каждой маске: ввести фразу без операторов, отправить, прочитать число «показов в месяц» по ТЕКСТУ страницы (`get_page_text`/`read_page`), не по CSS-селекторам — вёрстка Вордстата меняется, текст «показов в месяц» стабильнее.
4. Левая колонка «Что искали со словом …» — источник хвостов: явный мусор (длительная аренда, работа, соседние города) записать в журнал в `tails` с пустым `action` — решение примет человек на листе «Хвосты».
5. Темп: пауза 3–7 секунд между запросами, батчи по ~25 масок, между батчами 1–2 минуты. Безопасный темп НЕ подтверждён `[requires recheck]` — при первом прогоне зафиксировать фактический порог до капчи/троттлинга.
6. Перед каждым батчем проверять, что индикатор региона не слетел; слетел — перевыставить и повторить последнюю маску.
7. Оценку времени сказать пользователю до старта: ~100–200 масок ≈ 30–60 минут с паузами.

## Recovery And Edge Cases

- **Капча** → стоп немедленно, капчу не обходить; сказать пользователю, продолжить после его вмешательства с места обрыва (журнал).
- **Троттлинг** (пустые ответы, ошибки подряд) → удвоить паузы; повторилось → стоп с сохранённым прогрессом, доложить сколько собрано/осталось.
- **Потеря сессии посреди прогона** → стоп, логин делает пользователь, продолжить по журналу.
- **Нет подключения браузера** (Chrome MCP недоступен) → фолбэк «ручная проверка»: выдать пользователю маски батчами текстом, книгу собрать с пустыми частотами и явной меткой ручного режима на «Сводке»; вердикты — после ручного внесения частот.
- **Число не прочиталось по тексту** → не выдумывать: пометить маску в журнале `{"freq": null, "error": "not_parsed"}` и идти дальше; в конце отдать список непрочитанных на ручную проверку.
