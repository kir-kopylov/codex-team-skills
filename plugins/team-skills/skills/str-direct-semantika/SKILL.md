# Семантика Директа Для Посуточной Аренды (экспериментальный)

## Согласие На Запуск

Явный вызов — slash-команда, внутреннее имя skill или первая фраза из каталога — выполняйте сразу, без вопроса.

При автосрабатывании на смысловое сходство извлеките из текущего запроса действие пользователя, конкретный объект и короткое различие между процедурой навыка и обычным ответом. Затем без вводного объяснения заполните и покажите карточку:

Применить **«Семантика для посуточной аренды»** (@kir-kopylov; экспериментальный; обратная связь @kir-kopylov) для <семантики названных адресов>?

**С навыком:** география, маски, частоты и конфликты минус-слов собираются в Excel; вход и капчу проходит пользователь.

**Без навыка:** результат — идеи ключевых фраз без проверенных частот и защиты от конфликтов минус-слов.

Перед отправкой замените все placeholders сведениями из запроса: неизвестное не придумывайте. В карточке должны быть ровно три содержательные строки и не более 45 слов. Вопрос первым и один раз называет действие и объект. «С навыком» и «Без навыка» занимают по одной строке и одному предложению, показывают только различие и не повторяют запрос. Не добавляйте отдельное ограничение, таблицу, кодовую рамку, служебный жаргон или заголовок `Annotation N`; не показывайте внутреннее имя skill.

После карточки ждите ответа. При отказе выйдите из skill молча: решите задачу с нуля и больше не упоминайте skill.

## Обзор

Skill превращает список адресов STR-бизнеса в городе в рабочую книгу семантики для Яндекс.Директа: маски по группам спроса, частоты, вердикты, минус-лист без самоконфликтов, черновик кампаний. Общайтесь простым языком: «маски» и «минус-слова», а не «семантические кластеры».

Три правила, выученные на реальных прогонах (не нарушать):

1. **Сначала дёшево группировать, потом проверять.** Адреса группируются в кластеры по улицам и районам ДО веб-проверок; гео-проверка — одна на кластер, не на адрес. Обратный порядок сжигает треть бюджета токенов на подтверждение одного и того же района.
2. **Пустышки режет частота, а не мнение.** Не выбрасывайте маску потому, что «по улицам не ищут» — жд вокзал тоже «точка», а спрос там живой. Отсев только по частотному порогу из Вордстата; до частот маска — кандидат.
3. **Минус-лист проверяется против собственных масок.** Директ матчит минусы по лемме: минус «ночь» молча обнулит вашу же маску «квартира на ночь». Каждый минус проходит `minus-check`; конфликтные — в «спорное» с явным решением человека.

## Режимы И Входы

Режимы: **новый город** (полный цикл), **дозаливка** (новый кластер адресов в существующую книгу), **аудит минус-листа** (только `minus-check` по чужому списку).

Обязательные входы: город; адреса или кластеры; рамки спроса (только квартиры? почасовая? отели?). Опрос — ТОЛЬКО по недостающим входам, по одному вопросу за раз; известные рамки (из памяти или прошлой книги) не переспрашивать. Пороги вердиктов и region_id берутся из прошлой книги; если их нет — калибруются на этом прогоне и помечаются `[requires recheck]` до калибровки.

Перед любым вопросом проведи контрфактическую проверку:

Задавай только ближайший вопрос, ответ на который реально меняет результат.

## Процесс

1. **Группировка адресов** — по названиям улиц и известным районам, без агентов и веб-поиска. Результат: кластеры `C1..Cn` с улицами.
2. **Гео-проверка** — веб-поиском подтвердить район, метро, ориентиры: один запрос-проверка на кластер. Не выдумывать ориентиры без подтверждения.
3. **Генерация масок** — по вееру групп спроса из `references/spros-gruppy-str.md` (веер — ориентир под бизнес, не обязательный шаблон). Комментарий к маске ≤1 строка. Дедуп делает скрипт по нормализованным словоформам.
4. **Config** — собрать `config.json` по схеме из docstring `scripts/semantika.py`; первичная книга: `python3 scripts/semantika.py build --config cfg.json --out core.xlsx`.
5. **Частоты** — по механике `references/domain-playbook.md`: браузер пользователя, регион города, каждая снятая частота сразу в append-only `wordstat-progress.jsonl` в папке проекта (обрыв ничего не теряет); мусорные хвосты из выдачи — туда же. Капчу не обходить; пароли не вводить; нет браузера — фолбэк «ручная проверка» (маски пользователю батчем, частоты вносит он).
6. **Вердикты** — `semantika.py verdicts --config … --progress … --out …`: ниже нижнего порога «вон», между порогами «гипотеза», выше верхнего «в кампанию».
7. **Минус-лист** — `semantika.py minus-check`: конфликтные минусы становятся «спорное»; по каждому — явное решение в книге. Хвосты с действием «в минус-лист» добавить в config.
8. **Кампании** — строит скрипт по `references/campaign-rules.md`: только маски «в кампанию», 1 группа объявлений = 1 интент, кросс-минусовка детерминированная.
9. **Книга** — финальный `build` (или `merge --into` для дозаливки: бэкап автоматически, ручные колонки не трогаются). После ручных правок книга — единственный их носитель: пересборка только `--force` осознанно.
10. **Проверка целостности** — по гейтам самой книги: нет «спорных» минусов без решения (жёлтая подсветка чиста), нет вердиктов без частоты (красная подсветка чиста), «Кампании» непусты после вердиктов. При работе в checkout репо дополнительно `python3 -m pytest tests/test_str_direct_semantika.py`. Критик-агент полноты — опционально и только для нового типа бизнеса: стандартные проверки уже в скрипте.

## Границы

- Не выдавать частоты «из головы» — только из Вордстата или явная метка ручного режима.
- Не обходить капчу и не вводить пароли: логин в Яндекс делает пользователь сам.
- Не удалять минус-слова и маски автоматически — скрипт только помечает, решает человек.
- Не пересобирать книгу поверх ручных правок без `--force`; дозаливка — только `merge`.
- Не переносить адреса и данные клиентов в примеры и репо — только «Город N», «кластер C1».
- Не для SEO, ставок, бюджетов и Google Ads; разовая частота пары ключей — без развёртывания цикла.

## Definition Of Done

Книга с шестью листами (Сводка, Маски, Минус-слова, Гео-кластеры, Хвосты, Кампании); у каждой маски частота или явная метка ручного режима; ни одного «спорного» минуса без решения; «Кампании» непусты (после вердиктов); пороги и region_id откалиброваны или помечены `[requires recheck]`; подсветки-гейты книги чисты (красная — вердикт без частоты, жёлтая — спорный минус без решения).
