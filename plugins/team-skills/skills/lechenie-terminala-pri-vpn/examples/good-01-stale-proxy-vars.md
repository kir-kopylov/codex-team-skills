# Пример: залипшие переменные прокси при живом туннеле

## Вход

Человек: «Включил VPN, браузер работает, а `git push` висит и `curl` даёт `000` — почини». Оболочка исполнителя — `Git Bash`. Ранее VPN-приложение работало в режиме прокси, потом человек переключил его в туннельный режим.

## Ожидаемое Поведение

Агент идёт по дереву, сам выполняя команды, и не трогает VPN.

1. Класс маяка и симптом: пробивает внутристрановой `ya.ru` и внешний `github.com`. `ya.ru` даёт `200`, `github.com` — `000`. По таблице: сеть жива, целевой класс не проходит; VPN уже включён — значит идём в дерево прокси, а не «сеть мертва».
2. Транспорт: `git remote -v` показывает `https://…` — прокси-механика применима.
3. Переменные и конфиг: показывает прокси-переменные — стоят `HTTP_PROXY`/`HTTPS_PROXY` на `127.0.0.1`; `git config --global --get http.proxy` пуст. Улика — в переменных.
4. Безусловная проба в обход: `curl -s -m 10 --noproxy "*" ... github.com` даёт `200` за доли секунды. Диагноз: туннель жив, терминал душили только переменные — сразу к развязке А, `DNS` смотреть не нужно.
5. Развязка А: рабочая команда с очищенным окружением — `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy git push`; агент честно называет это обходом и предлагает постоянное лечение — выключить «системный прокси» в VPN-приложении и открыть новый терминал.
6. Контрольная проба: `git ls-remote origin` с тем же обходом — успех подтверждён делом, а не словами.

## Нельзя

Нельзя брать оба маяка из блокируемого класса (`google.com` + `github.com`) и по их `000` объявлять сеть мёртвой; просить человека переключать VPN до безусловной пробы в обход; ветвиться на `DNS` (реальные адреса туннель не опровергают); молча править глобальный конфиг `git` вместо сессионного обхода; объявлять успех без контрольной пробы той же командой.
