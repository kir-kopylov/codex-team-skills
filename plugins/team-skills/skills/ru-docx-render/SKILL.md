## Обзор

Это нижний, чисто технический слой пакета документов. Верхний skill (например, `remont-dogovor-i-raspiski` или `raspiska-o-poluchenii-deneg`) собирает смысл — текст, суммы, реквизиты, инварианты — и передаёт сюда уже готовую структуру. Задача `ru-docx-render` — превратить её в аккуратный `.docx` с единым оформлением, чтобы каждый верхний skill не переписывал вёрстку заново.

Стандарт оформления один на всех: шрифт `Times New Roman`, страница `A4`, поля верх/низ/лево/право = 2/2/2.5/1.5 см, заголовок по центру, тело по ширине, пустые графы личных данных остаются маркером «____», подписи — таблицей без видимых рамок.

## Естественные Входы

- «свёрстай договор/расписку в `docx` по стандарту»
- «отрендери готовый текст в `Word`»
- «собери `docx`: `Times New Roman`, поля, подписи»
- «сделай `Word`-файл из готовой структуры документа»
- «оформи документ как полагается — шрифт и поля»

## Процесс

1. **Примите готовую структуру.** Вход — либо `JSON` с непустым списком `blocks`, либо `markdown`-подмножество. Поддерживаемые блоки: `title`, `heading`, `para`, `city_date`, `signature_table`, `spacer`. Содержание уже собрано верхним слоем — не дополняйте и не правьте его по смыслу.
2. **Не заполняйте пустые графы.** Маркер «____» — это сознательно оставленное место для личных данных. Рендер переносит его как есть. Пустая графа в готовом `.docx` для этого skill — норма, а не дефект.
3. **Соберите файл.** Используйте `scripts/render_docx.py` и его хелперы: `new_doc` (страница, поля, базовый шрифт), `title`, `heading`, `para`, `city_date`, `signature_table`. Шрифт проставляется на каждый run (ascii + hAnsi + cs), чтобы кириллица не «съезжала» на дефолтный шрифт.
4. **Запуск через CLI.** `python3 scripts/render_docx.py --in <структура>.json --out <файл>.docx` (или `--in <текст>.md`). Выход обязан быть `.docx`; другой формат отклоняется.
5. **Верните путь к файлу.** Не делайте выводов о корректности содержания — за суммы, хронологию и реквизиты отвечает верхний skill.

## Границы

- Не сочинять содержание документа: текст, суммы и формулировки приходят сверху.
- Не проверять смысловые инварианты (итог = аванс + остаток, хронология, совпадение реквизитов) — это ответственность верхнего skill.
- Не заполнять пустые графы личных данных вместо человека: «____» остаётся «____».
- Не экспортировать в форматы кроме `.docx` (`PDF`, `ODT`, `HTML`).
- Не хранить и не вписывать приватные реквизиты в код или примеры: только синтетические данные.
