# Хороший Пример: Уже Сделанное Не Рекомендуется Повторно

## Вход

«Часть патчей уже смержена, часть находится в PR, а часть только предложена.
Изучи чат и не рекомендуй сделанное повторно».

## Ожидаемое Поведение

Skill сначала формулирует точную поведенческую дельту каждого кандидата, затем
без изменения repo и runtime проверяет доступные worktree, commits, открытые PR
и актуальный канонический `main`. Для каждого кандидата он указывает
`implementation_state`, `delta_match`, `runtime_state` и краткое проверяемое
основание. `MERGED + EXACT` получает `no library change`; точное изменение в
`PR_OPEN` переносится в «Уже реализуется» с действием продолжить этот PR; только
доказанный `PROPOSED_ONLY + NONE` участвует в рейтинге. При `PARTIAL` совпавшая
часть с `PR_OPEN` сразу переносится в «Уже реализуется», а остаток становится
новой самостоятельной дельтой. Для него skill заново проверяет все решающие
слои и заполняет собственные три поля состояния; только независимый
`PROPOSED_ONLY + NONE` допускает остаток в V1. Каждый следующий `PARTIAL`
повторяет этот цикл. Если остаток не уменьшается или повторяется, skill ставит
ему `implementation_state: UNKNOWN` и `delta_match: UNKNOWN` и останавливает
рекомендацию. Установка plugin не выводится из статуса PR или `main`.
Если доступный материал не позволяет сформулировать или проверить конкретную
дельту, первый ход заканчивается доказанным `UNKNOWN` без рекомендации, а не
обещанием проверить её позднее.

Если составная дельта требует признаки A и B, актуальный `main` содержит только
A, а целый head открытого PR содержит A и B, skill получает `PARTIAL` на снимке
`main` и `PR_OPEN + EXACT` на снимке PR. Он переносит всю дельту в «Уже
реализуется» и не собирает ложный `MERGED + EXACT` из доказательств разных
слоёв. Если ни один слой не содержит всю дельту, A и B выводятся отдельными
частями с их собственными состояниями доставки, после чего проверяется только
реальный остаток.

Если исторический commit C содержал всю дельту, но текущий tip T активной ветки
доставки отменил или удалил её, `COMMITTED + EXACT` запрещён: skill сравнивает
дельту с итоговым снимком T, а не с деревом C. Когда все решающие текущие слои
доступны и ни один не содержит дельту, результат — `PROPOSED_ONLY + NONE`;
когда активный tip или решающий статус PR подтвердить нельзя — `UNKNOWN`.
Закрытый незамерженный PR не считается активной доставкой: его head сам по себе
не даёт `PR_OPEN` или `COMMITTED`. Если та же дельта находится в отдельно
доказанном tip другой активной ветки, основанием служит именно этот tip.

## Нельзя

Нельзя считать слова «смержено» или «есть PR» доказательством, объявлять
недоступный решающий слой `PROPOSED_ONLY`, наследовать состояние исходной
дельты её остатку, объединять признаки разных слоёв в один `EXACT`, ранжировать
остаток до независимой проверки, зациклиться на неизменной дельте, смешивать
repo с runtime, считать исторический или отменённый commit текущей доставкой
или изменять Git, PR и установленный plugin ради инвентаризации.
