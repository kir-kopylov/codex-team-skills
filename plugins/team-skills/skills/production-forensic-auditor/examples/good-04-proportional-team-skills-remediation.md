# Хороший Пример: Пропорциональный Repair TeamSkills

## Вход

Пользователь даёт широкий forensic-разбор плана ремонта Windows-обновления небольшой библиотеки командных skills и просит пересобрать решение без оверинжиниринга. Буквальная цель: починить Windows update, совместимость проверки подписи с Windows PowerShell 5.1, существующий `RepairInstall` и Windows tests.

## Ожидаемое Поведение

Codex фиксирует класс продукта: это небольшая библиотека командных skills, а не управляемый корпоративный парк. В категорию `обязательно` он включает не более трёх направлений: совместимый подписанный Windows update вместе с PS5.1 signature, восстановление через `RepairInstall` и Windows tests для обоих путей. Эти направления и составляют итоговую пересборку.

MDM, KMS и production telemetry относятся к `только при дополнительных условиях`: они могут понадобиться при явно заданных управляемом парке, SLO, централизованном восстановлении или audit-требованиях. Новый control plane и новая update-платформа относятся к `вне scope` текущей цели. Широкий список возможных production-рисков остаётся аудитом и не превращается в разрешение внедрять их устранение.

## Нельзя

Нельзя добавлять MDM, KMS, telemetry, новый control plane или новую платформу обновлений. Нельзя потерять Windows update, PS5.1 signature, `RepairInstall` или Windows tests ради искусственного сокращения списка.
