# Хороший Пример: Пропорциональное Windows-Исправление TeamSkills

## Вход

Пользователь даёт широкий forensic-разбор Windows-доставки небольшой библиотеки командных skills и просит пересобрать решение без оверинжиниринга. В доступных authoritative tests и документации repo закреплён подписанный one-shot installer: обновление выполняется повторным запуском той же команды, а неудачная замена автоматически возвращает предыдущий plugin внутри текущего запуска. Отдельных пользовательских update, status и repair-команд нет.

## Ожидаемое Поведение

Codex сначала сверяет текущую delivery-модель с authoritative repo и только затем фиксирует класс продукта: это небольшая библиотека командных skills, а не управляемый корпоративный парк. В категорию `обязательно` он включает не более трёх направлений: signed one-shot Windows installer с проверкой подписи в Windows PowerShell 5.1; повторную установку через временную копию, backup и автоматический rollback при ошибке замены; Windows tests для подписи, установки, повторной установки и отката. Эти направления и составляют итоговую пересборку.

MDM, KMS и production telemetry относятся к `только при дополнительных условиях`: они могут понадобиться при явно заданных управляемом парке, SLO, централизованном восстановлении или audit-требованиях. Отдельные пользовательские update, status и repair-команды, новый control plane и новая update-платформа относятся к `вне scope` текущей цели. Широкий список возможных production-рисков остаётся аудитом и не превращается в разрешение внедрять их устранение.

## Нельзя

Нельзя добавлять MDM, KMS, telemetry, scheduled update service, новый control plane или новую платформу обновлений. Нельзя возвращать отдельные пользовательские update, status или repair-команды и нельзя потерять совместимую подпись, безопасную повторную установку или Windows tests ради искусственного сокращения списка.
