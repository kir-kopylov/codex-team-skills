# Хороший Пример: Нужный Safety-Механизм Оставлен Узким

## Вход

Пользователь раздражён сложностью установки расширений и говорит: «Уберите подписи и проверки пакета, это всё overengineering». Проверяемый контекст показывает, что пакет приходит из внешнего источника и после установки его scripts выполняются с правами пользователя.

## Ожидаемое Поведение

Codex формулирует outcome одним предложением: пользователь должен устанавливать расширение без выполнения подменённого кода.

В ledger cryptographic verification получает `keep`: боль конкретна, evidence показывает внешний trust boundary и выполнение кода, а цена удаления — компрометация машины. При этом отдельный background verifier, дублирующая база доверия и многоступенчатый scheduler могут получить `simplify`, если тот же invariant обеспечивает одна проверка непосредственно перед установкой.

Surviving invariant: пакет с неверной подписью не устанавливается. Единственный следующий шаг — проверить этот отказ на минимальной повреждённой fixture.

## Нельзя

Нельзя превращать anti-overengineering в слепое удаление safety controls. Нельзя объявлять всю существующую реализацию необходимой только потому, что один узкий invariant действительно нужен.
