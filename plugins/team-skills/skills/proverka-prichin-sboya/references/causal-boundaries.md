# Причинные Границы Технической Системы

Граница — место, где наблюдение может отделить один механизм от другого. Это не
обязательный порядок и не универсальная архитектура. Выбирайте только границы,
которые относятся к текущему outcome.

## Базовая Карта

| Граница | Что здесь можно наблюдать |
| --- | --- |
| Пользовательский результат | Видит ли пользователь требуемое рабочее состояние |
| Клиент или вызывающая сторона | Было ли целевое действие действительно начато |
| Процесс или runtime | Выполнил ли нужный код живой процесс |
| Конфигурация | Какое сохранённое значение использовал процесс |
| Данные или контракт | Соответствуют ли вход, schema и результат ожиданиям |
| Права и идентичность | Достигнут ли слой проверки полномочий |
| Интеграция или транспорт | Пересекли ли запрос и ответ границу компонентов |
| Внешняя зависимость | Какой наблюдаемый ответ дала удалённая сторона |
| Измерительный стенд | Относится ли лог, тест или монитор к реальному пути |

## Как Строить Карту

1. Начните с outcome и двигайтесь к ближайшему месту, где прямой сигнал
   пропадает.
2. Для каждого факта назовите источник и границу. Не переносите факт на соседний
   компонент без отдельного evidence.
3. Не добавляйте границу «на всякий случай». Она нужна, только если меняет выбор
   следующего probe.
4. Проверяйте измерительный стенд как обычный компонент: старый лог, mock,
   неверный профиль или другая среда могут создавать ложную картину.

## Не Линейная Лестница

Система может иметь параллельные зависимости, очереди, кэш и асинхронные
процессы. Поэтому два правила важнее фиксированного списка:

- причинный контраст должен находиться между двумя конкретными объяснениями;
- observation должен быть получен на той границе, где их прогнозы расходятся.

Если один переключатель одновременно меняет несколько границ, это составное
восстановительное действие, а не чистый диагностический опыт.

## Примеры Ошибочной Склейки

- живой процесс не доказывает пользовательский outcome;
- успешный transport не доказывает авторизацию;
- ответ API не доказывает применение результата downstream-компонентом;
- зелёный CI job не доказывает запущенную версию;
- внешний кейс не доказывает локальный механизм;
- локальный mock не доказывает работу внешнего провайдера.
