# Хороший Пример. Кто Обработал Событие

## Вход

Проверь причины сбоя. В стенде действие «Обновить сводку» показывает архивные
данные вместо свежих. Для одного входа зарегистрированы два обработчика.
Доступны журнал входящих событий и журнал выбора обработчика. Событие можно
проследить по идентификатору. Настройки пока не меняем.

## Ожидаемое Поведение

Codex берёт идентификатор одного вызова из контекста сбоя и сопоставляет
свежие записи входа и выбора. Две версии дают разные наблюдения:

- Если событие остановилось до выбора, тот же идентификатор есть в явной записи
  о прекращении обработки на предыдущем участке.
- Если сработал другой обработчик, запись выбора для того же идентификатора
  показывает обработчик архива.

Если запись выбора показывает обработчик свежих данных, обе версии
отвергнуты и проверка переходит на участок после выбора. Если журнал выбора
не покрывает нужный контекст, обработчик остаётся неизвестным. После
разрешённой правки Codex проверяет «Обновить сводку» и соседнее действие
«Открыть архив», если оно использует изменённые правила.

## Нельзя

Менять порядок правил до наблюдения, считать две регистрации доказательством
перехвата или объявлять событие потерянным только из-за пустого журнала.
