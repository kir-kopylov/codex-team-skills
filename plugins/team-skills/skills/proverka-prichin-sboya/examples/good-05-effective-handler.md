# Хороший Пример. Кто Обработал Событие

## Вход

Проверь причины сбоя. В стенде действие «Обновить сводку» показывает архивные
данные вместо свежих. Для одного входа зарегистрированы два обработчика.
Доступна трассировка входа и выбора. Журнал приёма покрывает часть вызовов.
Записи можно сопоставить по идентификатору. Настройки пока не меняем.

## Ожидаемое Поведение

Codex сверяет записи для одного вызова в контексте сбоя:

- Явная запись об остановке до выбора показывает, где прервалась обработка.
- Запись о приёме у обработчика архива подтверждает доставку ему. Если событие
  получил обработчик свежих данных, проверка переходит на участок после приёма.
- Если для этого вызова есть только запись выбора, Codex называет выбранного
  обработчика и оставляет получение неизвестным. Правку, которая опирается
  на предположение о доставке, откладывает даже при наличии разрешения.

После разрешённой правки Codex сравнивает с ожидаемым результат «Обновить
сводку» и проверяет, что «Открыть архив» по-прежнему выдаёт архивные данные,
если это действие использует изменённые правила.

## Нельзя

Менять порядок правил по одному списку привязок, считать запись выбора
доказательством приёма или объявлять событие потерянным из-за пробела в журнале.
