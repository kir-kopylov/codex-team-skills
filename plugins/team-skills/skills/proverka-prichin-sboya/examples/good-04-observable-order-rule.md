# Хороший Пример: Фактическое Правило Без Сбоя

## Вход

Пользователь замечает воспроизводимое поведение непрозрачной системы: при
добавлении трёх элементов интерфейс показывает их в неожиданном порядке. Ошибки
нет. Нужно установить, сортирует ли система элементы по времени создания или
по названию. Доступна безопасная тестовая область; менять рабочие данные нельзя.

## Ожидаемое Поведение

Codex не объявляет внутренний алгоритм сортировки. Он фиксирует две модели:

- A: порядок определяется временем создания;
- B: порядок определяется названием.

Один безопасный различающий опыт — в тестовой области создать два синтетических
элемента так, чтобы более поздний элемент шёл раньше по алфавиту, сохранив
версию, профиль, фильтры и способ просмотра.

Если интерфейс показывает более поздний элемент первым, наблюдение согласуется
с B; если первым остаётся ранний элемент — с A. После опыта Codex возвращает:

```text
Проверенные условия: текущая версия, тестовая область, два видимых элемента,
одинаковый профиль и фильтры.
Наблюдение: элемент, идущий раньше по алфавиту, показан первым независимо от
порядка создания.
Поведенческий контракт: при этих условиях система наблюдаемо упорядочивает
элементы по названию.
Граница вывода: другие версии, области, типы элементов и скрытые фильтры не
проверены.
Не установлено: внутренняя реализация, замысел разработчика, штатность или баг.
```

## Нельзя

Нельзя писать «разработчики реализовали алфавитную сортировку» или «это штатное
поведение». Нельзя переносить контракт на другие версии и типы элементов.
Нельзя менять рабочие данные ради опыта.
