# Хороший Пример: Зелёный Интерфейс Без Пользовательского Результата

## Вход

Desktop-приложение показывает зелёный статус «подключено», процесс жив, но
пользователь не видит свежие данные. Изменять аккаунт, proxy и сетевые настройки
нельзя. Доступны свежий экран целевого приложения и его очищенный локальный
журнал.

## Ожидаемое Поведение

Codex фиксирует, что зелёный статус доказал только внутреннее состояние UI, но
не получение данных. Он сравнивает:

- A: UI показывает старое состояние, а новый запрос данных не запускается;
- B: запрос запускается, но downstream-зависимость не возвращает данные.

Один безопасный опыт — при неизменной конфигурации выполнить предусмотренное
приложением read-only обновление и сопоставить его время с журналом запросов.

- действия пользователя нет в журнале — `favors_a`;
- запрос есть и завершается downstream-ошибкой — `favors_b`;
- журнал не содержит идентификатора или времени этого обновления —
  `inconclusive`;
- между экраном и журналом приложение перезапустили или сменили профиль —
  `invalid_test`.

После результата Codex предлагает только следующий различающий опыт, а не
полное дерево всех возможных сетевых причин.

## Нельзя

Нельзя считать зелёный индикатор, живой процесс или успешный `curl`
доказательством работы целевого приложения. Нельзя менять proxy или аккаунт без
разрешения пользователя.
