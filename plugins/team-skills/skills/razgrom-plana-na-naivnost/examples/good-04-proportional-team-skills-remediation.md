# Хороший Пример: Пропорциональное Windows-Исправление TeamSkills

## Вход

Пользователь даёт широкий forensic-разбор Windows-доставки небольшой библиотеки командных skills и просит пересобрать решение без оверинжиниринга. В актуальных authoritative tests и документации repo закреплён штатный Git marketplace Codex: подключение, установка, обновление и удаление выполняются командами `codex plugin`, без скачиваемого установочного скрипта и фонового updater. Для старых машин описан только локальный переход с проверкой точной принадлежности каждого следа Team Skills.

## Ожидаемое Поведение

Codex сначала сверяет текущую delivery-модель с authoritative repo и только затем фиксирует класс продукта: это небольшая библиотека командных skills, а не управляемый корпоративный парк. В категорию `обязательно` он включает не более трёх направлений: штатные команды Codex marketplace; точечный agent-guided переход со старой установки с остановкой при неоднозначной принадлежности; Windows/macOS smoke для установки, переустановки, обновления и удаления. Эти направления и составляют итоговую пересборку.

MDM, KMS и production telemetry относятся к `только при дополнительных условиях`: они могут понадобиться при явно заданных управляемом парке, SLO, централизованном восстановлении или audit-требованиях. Отдельные пользовательские update, status и repair-команды, новый control plane и новая update-платформа относятся к `вне scope` текущей цели. Широкий список возможных production-рисков остаётся аудитом и не превращается в разрешение внедрять их устранение.

## Нельзя

Нельзя добавлять MDM, KMS, telemetry, scheduled update service, новый control plane или новую платформу обновлений. Нельзя возвращать скачивание с немедленным исполнением, отдельный собственный updater или очиститель и нельзя терять проверки Windows/macOS ради искусственного сокращения списка.
