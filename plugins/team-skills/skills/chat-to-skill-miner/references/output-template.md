# Шаблон Результата

Используйте этот состав, когда пользователь просит полный результат поиска кандидатов. Не заполняйте секции объёмом ради формы.

## Доступный Материал

- Что изучено.
- Что недоступно или сжато.
- Где проходит граница уверенности.

## Повторяемые Сигналы

Для каждого сигнала назовите намерение пользователя, повторяемую боль или сбой, требуемое поведение и границу качества либо безопасности.

## Кандидаты

Для каждого кандидата укажите:

- имя папки;
- тип;
- назначение одной фразой;
- естественные триггеры;
- повторяемое свидетельство;
- границу применения;
- признаки проверяемости: каким примером, fixture или наблюдаемым результатом можно доказать ожидаемое поведение;
- существующий ближайший skill, если он найден;
- поведенческая дельта относительно него;
- `implementation_state`: `PROPOSED_ONLY`, `WORKTREE_ONLY`, `COMMITTED`,
  `PR_OPEN`, `MERGED` или `UNKNOWN`;
- `delta_match`: `EXACT`, `PARTIAL`, `NONE` или `UNKNOWN`;
- `runtime_state`: `INSTALLED`, `NOT_INSTALLED` или `UNKNOWN`;
- краткое проверяемое основание: один слой-снимок, наблюдаемый объект и его
  состояние; не объединяйте признаки разных слоёв в один `delta_match`;
- для `COMMITTED` — активная ветка доставки, её точный tip, результат проверки
  достижимости реализующего commit из tip и `delta_match` на итоговом снимке
  tip; исторический commit и закрытый незамерженный PR не считаются текущей
  доставкой;
- для составной дельты без `EXACT` на одном слое — отдельный блок каждой
  совпавшей части с её собственным состоянием доставки;
- уже реализованная часть и остаточная дельта, если `delta_match: PARTIAL`;
- для каждого остатка после `PARTIAL` — отдельный повтор этого блока с его
  собственными `implementation_state`, `delta_match`, `runtime_state` и
  основанием; состояние родительской дельты не наследуется;
- вердикт относительно библиотеки: `new skill`, `patch existing skill`,
  `shared reference/test` или `no library change`;
- баллы и приоритет.

## Уже Реализуется

Сюда вынесите кандидатов и каждую совпавшую часть дельты с доказанным на
актуальном снимке соответствующего слоя состоянием `WORKTREE_ONLY`,
`COMMITTED` или `PR_OPEN`. Назовите доказанную часть, текущий слой доставки и
одно действие для продолжения существующей работы. Исторический или отменённый
commit и head закрытого незамерженного PR сюда не входят. Не включайте
актуально доставляемые части повторно в рекомендацию V1; остаток после
`PARTIAL` проверяйте отдельно.

## Рекомендация V1

Выберите не более 1–3 ещё не реализованных кандидатов или остаточных дельт,
которые после собственной проверки получили `PROPOSED_ONLY + NONE`. Для
каждого объясните, почему он первый, что предотвращает, какое свидетельство
делает его повторяемым и какая неопределённость ещё может его снять. `MERGED +
EXACT` получает `no library change`; `UNKNOWN` ожидает проверки решающего слоя
и не входит в V1. Если итерация `PARTIAL` не уменьшила остаток или повторила
его, зафиксируйте для остатка `implementation_state: UNKNOWN` и `delta_match:
UNKNOWN`, назовите отсутствие прогресса и остановите цикл.

## Не Формализовать

Перечислите отклонённые разовые, небезопасные, слишком широкие или низкосигнальные идеи и кратко назовите причину.

## Передача После Выбора

Если пользователь уже выбрал кандидат, укажите только его имя, причину прохождения рейтинга, доказательства и неопределённость для следующего этапа. Полный контракт, workflow, состав ресурсов и набор приёмочных проверок здесь не проектируйте; передайте выбранный кандидат в `skill-methodologist`.
