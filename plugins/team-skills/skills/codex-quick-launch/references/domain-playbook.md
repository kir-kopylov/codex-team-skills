# Domain Playbook

## Что Нельзя Потерять

- Разделять состояние файла на диске, загрузку runtime, видимость в slash-меню и фактическую позицию в списке.
- После изменения локальной skill проверять новую задачу или иной свежий UI-state, если текущая поверхность кеширует каталог.
- Считать порядок меню гипотезой, пока не получен свежий скрин или иной наблюдаемый UI-state.
- Сохранять прежний рабочий вызов, пока пользователь явно не выбрал замену.

## Что Надо Обезличить

- Личные пути, названия задач, скриншоты, содержимое буфера обмена и тексты пользовательских промптов.
- Имена аккаунтов, локальные настройки, идентификаторы задач и raw application logs.

## Interface Mechanics

- Поддерживаемые механизмы Codex меняются между версиями; проверяйте текущую среду перед советом.
- Legacy custom prompts и skills нельзя считать взаимозаменяемыми без проверки доступности в конкретном runtime.
- Короткий префикс имени может помочь только при сортировке по имени; это не API закрепления.

## Recovery And Edge Cases

- Если новая skill не видна, не создавайте цепочку дублей. Сначала проверьте новый UI-state и доступность механизма.
- Если UI-недоступен, завершайте с `не подтверждено` и одним запросом на свежий скрин, а не моделируйте расположение меню.
