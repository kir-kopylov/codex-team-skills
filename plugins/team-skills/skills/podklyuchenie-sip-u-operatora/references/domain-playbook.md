# Domain Playbook

## Что Нельзя Потерять

- Роль «Координатор лицевого счёта» является прямым признаком доступного
  операторского контекста; видимость меню сама по себе роль не доказывает.
- «МультиФон Бизнес» и виртуальная АТС — разные продукты. Не заменять один
  другим из-за похожего описания IP-телефонии.
- Уровни доказательства различаются: публичная кнопка → открытая форма →
  выполненный submit → зарегистрированное обращение → активная услуга.
- Перед новой заявкой проверять все релевантные вкладки обращений, включая
  обращения из кабинета и прочие обращения.
- Для `request_registered` сохранять в ответе идентификатор, статус и время
  наблюдения. Для `activated` повторно читать услугу или заказ.
- Текущие цена, обязательства и влияние на маршрутизацию читаются только в
  живом кабинете непосредственно перед действием.

## Что Надо Обезличить

- Полные корпоративные номера, контакты для уведомлений и имена сотрудников.
- Названия организаций, реальные лицевые счета, subscriber IDs и request IDs.
- SIP login, password, token и другие credentials.
- Raw logs, приватную переписку, query parameters и снимки личного кабинета.
- Локальные пути пользователя и содержимое приватного профиля компании.

## Interface Mechanics

- Авторизованный кабинет: `b2blk.megafon.ru`.
- Типовые URL patterns:
  - `/account/info/<account-id>/general` — контекст лицевого счёта;
  - `/products` и раздел «Тарифы и услуги» — поиск доступной услуги;
  - `/inquiries/inquiry/<request-id>` — доказательство зарегистрированного обращения.
- Значимые текстовые anchors:
  - «Координатор лицевого счёта»;
  - «Тарифы и услуги»;
  - «Заказы и обращения»;
  - «Выполнить действие. Подключение/отключение услуг и опций»;
  - «Нужная услуга отсутствует в разделе "Тарифы и услуги"»;
  - «Название услуги или опции»;
  - «Подключение»;
  - «Ожидает обработки».
- Сначала искать услугу на точном абоненте. Если она отсутствует, это не
  является доказательством неподдерживаемости: проверить путь обращения.
- Публичная страница продукта может содержать «Подключить», но переход способен
  открыть общий `/dashboard` без продукта и номера. Такой переход — только
  навигация, не начало подключения.
- Поле SMS-уведомления может быть предзаполнено контактом неподходящего типа.
  Не менять его догадкой: проверить требования поля и использовать
  подтверждённый контакт из приватного профиля.
- Предпочитать semantic anchors и повторное чтение состояния. CSS selectors и
  координаты допустимы только как локальная подсказка, не как единственное
  доказательство.

## Recovery And Edge Cases

- После исчезнувшего подтверждения сначала перечитать услуги, заказы и
  обращения. Повторный submit разрешён только после доказанного отсутствия
  результата.
- Если публичная ссылка потеряла контекст, вернуться в точного абонента и
  продолжить из кабинета, а не из рекламной страницы.
- Если услуга не найдена, выбрать обращение об отсутствующей услуге и заполнить
  точный продукт, действие и параметры приватного профиля.
- Если один раздел обращений пуст, проверить остальные релевантные вкладки
  перед выводом «дубля нет».
- Если новая форма сохраняет номер, действие и risk profile однозначно,
  разрешено продолжить и записать интерфейсное исключение.
- Если изменились цена, маршрутизация, выбранный абонент или смысл submit,
  вернуть `blocked_human_action`.
- После двух неверных гипотез об одном элементе прекратить угадывание и
  запросить одно действие человека.
