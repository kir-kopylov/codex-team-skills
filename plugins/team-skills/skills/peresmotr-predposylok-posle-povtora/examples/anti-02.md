# Анти-Пример

## Вход

Unit test падает с точной assertion: expected `404`, got `200`. Код и тест рядом, причина видна: handler возвращает успешный ответ для отсутствующего объекта. Пользователь просит быстро исправить.

## Ожидаемое Поведение

Skill не нужен:

```text
stop_condition: нет repair-loop
gate: failing assertion напрямую проверяет bug
next_step: исправить handler или тест обычным engineering workflow
```

Здесь нет затяжного loop, ложных промежуточных признаков или необходимости external-case pivot.

## Нельзя

Нельзя тратить время на поиск похожих случаев и "смену рамки", когда локальная причина уже проверяема напрямую.
