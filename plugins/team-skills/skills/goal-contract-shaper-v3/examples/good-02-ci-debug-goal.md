# Хороший Пример: цель с CI и production gaps

## Вход

Пользователь пишет: "Проверь цель для /goal: добиться зеленого CI в PR. Нельзя менять бизнес-логику без моего подтверждения. Если нужен секрет, доступ к GitHub Actions или ручной approve, агент должен остановиться".

## Ожидаемое Поведение

Codex применяет `goal-contract-shaper-v3`, потому что задача итеративная: прочитать check, воспроизвести сбой, внести минимальную правку, снова проверить. Он не чинит CI сразу, а формирует контракт.

Контракт должен выявить: что считается финалом, что такое одна итерация, какие проверки допустимы локально и в GitHub Actions, какие файлы можно менять, какие действия запрещены, как вести лог гипотез и команд, когда остановиться, что делать при auth, rate limit, missing secret или required approval.

## Нельзя

Нельзя запускать исправление до утверждения контракта, менять unrelated files, обходить auth, пушить в PR или объявлять CI зеленым по предположению без внешнего статуса проверки.
