# Проверка Реального Состояния Библиотеки Навыков

## Согласие На Запуск

Явный вызов — slash-команда, внутреннее имя skill или первая фраза из каталога — выполняйте сразу, без вопроса.

При автосрабатывании на смысловое сходство извлеките из текущего запроса действие пользователя, конкретный объект и короткое различие между процедурой навыка и обычным ответом. Затем без вводного объяснения заполните и покажите карточку:

Применить **«Проверка реального состояния библиотеки навыков»** (@kir-kopylov; экспериментальный; обратная связь @kir-kopylov) для <проверки названной библиотеки или навыка>?

**С навыком:** репозиторий, marketplace, установленный пакет, личные копии и текущая сессия проверяются раздельно; ненаблюдаемое остаётся неизвестным.

**Без навыка:** результат — проверка одного слоя, смешивающая опубликованное, установленное и загруженное состояние.

Перед отправкой замените все placeholders сведениями из запроса: неизвестное не придумывайте. В карточке должны быть ровно три содержательные строки и не более 45 слов. Вопрос первым и один раз называет действие и объект. «С навыком» и «Без навыка» занимают по одной строке и одному предложению, показывают только различие и не повторяют запрос. Не добавляйте отдельное ограничение, таблицу, кодовую рамку, служебный жаргон или заголовок `Annotation N`; не показывайте внутреннее имя skill.

После карточки ждите ответа. При отказе выйдите из skill молча: решите задачу с нуля и больше не упоминайте skill.

## Обзор

Этот skill отвечает не на вопрос «какие файлы где-то лежат», а на вопрос «что доказано на каждом слое прямо сейчас». Он строит read-only карту пяти независимых состояний:

```text
удалённый main
  → marketplace-источник
  → установленный plugin
  → личные одноимённые кандидаты
  → список навыков текущей сессии
```

Наличие новой версии слева не доказывает, что она дошла до слоя справа. Skill показывает первое наблюдаемое расхождение, но не придумывает причин там, где один из слоёв недоступен.

## Естественные Входы

- «Какая версия библиотеки навыков реально активна?»
- «Почему новый навык не виден?»
- «Сравни GitHub, установленный plugin и текущую сессию».
- «Проверь, не перекрывает ли локальный skill командный».
- «Где именно застряло обновление Team Skills?»

## Допустимые Статусы

- `OBSERVED_MATCH` — оба соседних слоя наблюдались и совпали по проверяемому признаку;
- `OBSERVED_MISMATCH` — оба соседних слоя наблюдались и различаются;
- `NOT_INSTALLED` — штатная CLI наблюдаемо не показывает установленный plugin;
- `POTENTIAL_PERSONAL_SHADOW` — в проверенном личном корне есть точное одноимённое совпадение, но приоритет загрузки ещё не доказан;
- `OBSERVED_PERSONAL_SHADOW` — источник реально загруженного skill наблюдаем и указывает на личную копию;
- `UNKNOWN_COMMAND_FAILED` — read-only команда не выполнилась или вернула неразбираемый результат;
- `UNKNOWN_NOT_EXPOSED` — интерфейс не возвращает нужный commit, semver, source или path;
- `UNKNOWN_SESSION_NOT_OBSERVED` — список навыков именно текущей сессии недоступен наблюдению.

`unknown` — результат проверки, а не повод заполнить пробел догадкой.

## Процесс

### 1. Зафиксировать Вопрос И Время

Назовите проверяемый skill или версию, текущую машину/профиль в допустимой обезличенной форме и UTC-время начала. Прочитайте соседний `known-exceptions.yaml` и `references/domain-playbook.md`.

### 2. Проверить Удалённый Main

Read-only способом получите текущий SHA ветки `main` репозитория `kir-kopylov/codex-team-skills`. Из того же SHA прочитайте `plugins/team-skills/.codex-plugin/plugin.json` и, если вопрос о конкретном skill, наличие его каталога и registry-файлов.

Не используйте локальный checkout как доказательство удалённого `main`. Если сеть, GitHub или чтение конкретного SHA недоступны, поставьте `UNKNOWN_COMMAND_FAILED` и продолжите с остальными слоями.

### 3. Проверить Marketplace-Источник

Выполните `codex --version`, `codex plugin --help` и `codex plugin list --json`. Из ответа текущего запуска берите только реально возвращённые поля: marketplace/source/ref или их отсутствие. Не вычисляйте snapshot marketplace по имени cache-каталога.

Если CLI не запускается или JSON не разбирается, этот слой получает `UNKNOWN_COMMAND_FAILED`. Если CLI не отдаёт commit/ref marketplace, укажите `UNKNOWN_NOT_EXPOSED`; не приравнивайте source URL к конкретному SHA.

### 4. Проверить Установленный Plugin

Из того же JSON найдите ровно одну запись `team-skills@codex-team-skills` и зафиксируйте `version`, `enabled`, `installedPath` и source лишь когда эти поля возвращены. Затем безопасно проверьте, что `installedPath` — обычный каталог внутри текущего Codex home, и прочитайте из него plugin manifest и наличие проверяемого skill.

Нет записи — `NOT_INSTALLED`. Несколько записей, path escape, symlink, несовпавший manifest или неизвестная структура — наблюдаемое расхождение либо `UNKNOWN_NOT_EXPOSED`, но не автоматическая очистка.

### 5. Проверить Личные Одноимённые Кандидаты

Сначала установите, какие пользовательские корни навыков реально относятся к текущей поверхности. Проверяйте только непосредственные каталоги под этими корнями. Не обходите repo-scoped, системные и plugin-каталоги как «личные».

Кандидат получает `POTENTIAL_PERSONAL_SHADOW`, только если это обычный каталог без выхода по ссылкам, имя папки и frontmatter `name` совпадают, а такое имя есть в установленном plugin. Само совпадение не доказывает приоритет загрузки. `OBSERVED_PERSONAL_SHADOW` разрешён лишь когда текущая поверхность прямо показывает источник загруженного skill.

### 6. Проверить Текущую Сессию

Используйте только список skills или metadata, предоставленные самой текущей сессией. Проверьте наличие конкретного skill или контрольного `team-skills:production-forensic-auditor`.

Не восстанавливайте список сессии из cache, `installedPath`, каталога repo или памяти о предыдущем чате. Если текущая поверхность не раскрывает список, поставьте `UNKNOWN_SESSION_NOT_OBSERVED`. Если список раскрывает имя, но не версию пакета, подтверждайте только видимость имени, а semver сессии оставляйте `UNKNOWN_NOT_EXPOSED`.

### 7. Найти Первое Доказанное Расхождение

Сравнивайте только соседние слои и только общий наблюдаемый признак:

- remote semver против marketplace/installed semver, когда обе стороны известны;
- установленный manifest и каталог skill против JSON plugin;
- точное личное совпадение против наблюдаемого источника загруженного skill;
- установленное наличие skill против списка текущей сессии.

Первый `OBSERVED_MISMATCH` — локализация разрыва, не автоматически его причина. Если перед предполагаемым разрывом есть unknown, формулируйте «причина не локализована» и называйте недостающее наблюдение.

### 8. Выдать Карту Без Изменений

Покажите по каждому слою:

- наблюдаемое значение;
- источник доказательства и время;
- статус;
- что именно этот факт доказывает и чего не доказывает.

Затем дайте одну строку: «Первое доказанное расхождение: …» или «Расхождение не локализовано: …». Если пользователь после диагноза просит обновить, переустановить, перенести дубль или перезапустить Codex, это новая изменяющая задача для `team-skills-maintenance`; не выполняйте её внутри этого skill.

## Формат Результата

```text
Проверено в: [UTC]
Удалённый main: [SHA, semver, наличие skill, status, evidence]
Marketplace: [source/ref или unknown, status, evidence]
Установленный plugin: [id, semver, enabled, наличие skill, status, evidence]
Личные кандидаты: [имена и potential/observed либо ничего, status, evidence]
Текущая сессия: [видимость имени; semver или unknown, status, evidence]
Первое доказанное расхождение: [слой A → слой B либо не локализовано]
Изменения среды: не выполнялись
```

## Границы

- Не выполнять `marketplace add/upgrade/remove`, `plugin add/remove`, `git pull`, перемещение, карантин, удаление, правку config или перезапуск.
- Не выдавать remote `main`, marketplace, cache, установленный plugin и текущую сессию за одно состояние.
- Не считать каталог в cache доказательством активной версии.
- Не считать точную личную копию фактическим перекрытием без наблюдаемого источника загруженного skill.
- Не утверждать semver текущей сессии, если сессия показывает только имена.
- Не скрывать failed/unknown слой ради удобного диагноза.
- Не публиковать абсолютные личные пути, содержимое личных skills, токены или raw logs.

## Опрос После Использования

Опрос задаётся один раз после выдачи полной карты пяти слоёв или явного диагностического блокера, не посреди проверки. Если пользователь уже ответил «пропустить» в этой сессии, не переспрашивайте.

```text
Опрос по навыку:
1. Что в работе этого навыка было полезно?
2. Что стоит доработать в процедуре или формате ответа?
Можно ответить коротко или написать "пропустить".
```

Если пользователь ответил, сохраните санированную карточку в `~/.codex/skill-runs/team-skills-reality-check/usage-feedback.jsonl` — лучше через bundled script:

```bash
python3 scripts/log_usage_feedback.py --liked "..." --improve "..." --outcome "..."
```

Script перед записью редактирует приватные пути, контакты и token-like строки и сохраняет в JSONL `redaction_applied` и `redaction_types`. Если запись невозможна из-за sandbox, прав или отсутствия tools, не делайте вид, что лог сохранён: скажите об этом и покажите короткую JSONL-карточку для ручного сохранения. Raw-ответы, контакты, пути и секреты не коммитить.

## Логирование Сбоев

Перед выполнением прочитайте локальный `known-exceptions.yaml` как список уже известных случаев и применяйте подходящее `do_next_time` без нового поиска.

Если пользователь поправил skill, tool/API/browser упал, нарушен режим работы, пришлось искать workaround или skill сделал ложное предположение, запишите приватную карточку в `~/.codex/skill-runs/team-skills-reality-check/exception-log.jsonl`.

Пишите факты: что skill хотел сделать, что сделал, где сломался, какая предпосылка была ложной и что сделать в следующий раз. Если поле неизвестно, пишите `unknown`. Raw logs не коммитить.

## Definition Of Done

- Все пять слоёв представлены наблюдением или явным unknown со временем и источником.
- Remote SHA и semver взяты из одного commit, а установленное состояние — из JSON текущего запуска и проверенного manifest.
- Личный одноимённый каталог назван только кандидатом, пока источник загруженного skill не наблюдался.
- Видимость текущей сессии не выведена из файловой системы.
- Названо первое доказанное расхождение либо точное недостающее наблюдение.
- Ни один файл, plugin, marketplace, config, процесс или сессия не изменены.
